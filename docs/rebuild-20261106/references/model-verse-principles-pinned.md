# 仿真工具各模块计算原理

> 对应仓库 model-verse/LLM-Viewer-main。所有模块的共同底层是 **roofline**:
> 一段计算耗时 = max(搬数据的时间, 做计算的时间)。
> - 搬数据时间 = 要读写的字节数 ÷ 带宽
> - 做计算时间 = 运算次数 ÷ 峰值算力
> 两者取大者:哪个慢哪个就是瓶颈。

---

## 0. 两种计算方式

| 视图 | 口径 | 公式来源 |
|---|---|---|
| 分析视图 | 逐算子 roofline,按层数累加 | model_analyzer.py |
| 投机收益视图 | 量级解析,整步一次算 | spec_gain_model.js |

两套公式假设不同,数字不互换。另有一个离散事件引擎(serving_sim)和三个生成管线专用仿真。

## 1. 分析视图(逐算子 roofline)

**decode 一步的每层耗时**(权重读 + KV 读 + attention 计算,取瓶颈):

```
每层 = max(
  (权重总量÷TP + KV字节) ÷ 单卡带宽,              ← 访存
  (2×参数量÷TP + attention FLOPs) ÷ 单卡算力       ← 计算
)
单步 = 每层 × 层数 + 收尾条目(lm_head)
```

- 权重总量 = 参数量 × 每参数字节数(如 17B × 2B = 34GB)。TP 把权重切开,每卡只存/读 1/TP — 所有卡同时各读各的,读取时间 = (权重÷TP) ÷ 单卡带宽
- KV 字节**不 ÷TP**:GQA 的 KV 头随 TP 正常切分;KV 头数少于 TP 卡数时(如 MLA 单 KV 流)每卡复制读全量 — 按 vLLM 行为(本工具唯一借用的外部口径)
- 2 = 一次乘加按 2 次浮点计(乘 + 加);每生成一个 token,每个权重参与一次乘加,所以每 token 计算量 = 2×参数量。TP 同样切开计算:每卡算 2×参数量÷TP
- attention FLOPs ≈ 4×头数×头维×序列长×batch(花在 QK 和 SV 两个矩阵乘),再乘 全注意力层数÷总层数(混合架构如 Qwen3.5 只有 15/60 层是全注意力,线性注意力层不按此算——单列条目)
- 等价的集群视角:权重总量 ÷ (带宽×TP)、2×参数量 ÷ (算力×TP) — 算出的时间相同
- 开 FlashAttention 时按片上缓存分块,减少重复读取
- 量化影响两处:字节数下降;且权重/激活/KV **全部 ≤8bit 时峰值算力切换到 INT8 档**(否则 FP16 档,calibration.get_hw_info)

**prefill**:序列一次全进,计算量随序列长平方增长(attention 矩阵),通常转为算力受限。

**chat 阶段** = prefill 一次 + decode 在生成区间取采样点(最多 10 个:n_divide = min(10, 生成长度),np.linspace(seq+1, seq+gen, n_divide))累计,每点乘 生成长度÷平均接受长度。投机解码通过提高"平均接受长度"减少 decode 步数。

**投机解码**:分析视图支持 MTP(微头串行 k 步)与 DFlash(块扩散并行×iters)两种草稿建模;DSpark 不单独建草稿耗时,其效果折算进接受长度。接受长度 τ = (1−α^(k+1))÷(1−α),实测值优先,可再乘宽容倍数。

**MoE**:每 token 只激活 top-k 专家,但 decode 一步实际要读的专家是这一步所有 token 选中专家的并集。权重按期望覆盖率读取:1−(1−1/专家数)^(token数×k)。例:512 专家×top10×100 token → 只读约 18% 的专家权重;prefill token 多 → 覆盖率≈1 等价全量读。

## 2. 投机收益视图(量级解析口径)

**估算流水线**:模型 config + 硬件表 + 滑条 → 算出三类量(权重字节、KV 字节、FLOPs)→ 除以带宽/算力 → 取瓶颈 → 加常数 → 得到三个时长(**t_base** 无投机基线单步 / **t_verify** 验证 γ+1 个 token / **草稿**)→ 代入 **S = τ ÷ (η + c)**。τ 是收益,η 和 c 是成本。

**下面用默认打开页面时的配置把每个数字走一遍**(DeepSeek V4.1-Flash,16B 激活,W8A8,32K 上下文,B=1,TP=8,HBM 1.2TB/s,算力 376T,SRAM 12TB/s,命中率 5%,通信 0.85ms,γ=5,α=0.72,DSpark 草稿)。每个数都能在结果区"点击色块"的明细里对上。

### 2.1 基线单步 t_base

| 步骤 | 公式 | 代入 | 结果 |
|---|---|---|---|
| ① 权重字节 | 激活参数×精度字节×MoE扩散 | 16B×1B×1.00(扩散=1+0.08×log2(B),B=1 时=1) | 16.0 GB |
| ② KV 字节 | B×ctx×1024×KV每token字节 | 1×32×1024×890B÷1e9 | 0.029 GB |
| ③ 有效带宽 | 1÷(命中率÷SRAM簇 + (1−命中率)÷HBM簇) | 5%÷96TB/s + 95%÷9.6TB/s | 10.05 TB/s |
| ④ 访存耗时 | (①+②) ÷ ③ | 16.03÷10050 | **1.595 ms** |
| ⑤ 计算耗时 | FLOPs ÷ (算力×TP×0.75) | 513 GFLOPs ÷ 2256 TFLOPS | **0.227 ms** |
| ⑥ t_base | max(④,⑤) + 0.15×min + 通信常数 | 1.595 + 0.034 + 0.85 | **2.479 ms → 基线 403 tok/s** |

- ③ 里的"簇"= 单卡×TP(96 = 12×8,9.6 = 1.2×8)
- ⑤ 的 FLOPs = 2×激活参数×M_pad(16) + B×ctx×4×dAttn÷1e9 = 512 + 1.1 ≈ 513;M_pad = ⌈B÷M_tile⌉×M_tile(不足分块的行补零);0.75 是内置 MFU
- ⑥ 的 0.15×min 是访存/计算重叠系数,0.85 是「单步通信+launch」滑条

### 2.2 验证单步 t_verify(投机要付的第一笔成本)

验证一步并行算 **B×(γ+1) = 6 个查询位**:
- 权重照读一遍 → 访存 1.780 ms(MoE 模型此处扩散更大: B×(1+0.35γ) 并入 batch 再取对数)
- KV 读放大 ×(1+γ÷ctx) = 1.00015(ctx 长时可忽略;ctx 短时明显)
- attention FLOPs ×1.2(树形掩码折算)
- t_verify = 1.780 + 0.034 + 0.85 = **2.665 ms**

**η = t_verify ÷ t_base = 2.665 ÷ 2.479 = 1.075** — 一次验证比一次普通前向贵 7.5%,这是投机的固定成本。

### 2.3 草稿耗时 c(投机要付的第二笔成本)

DSpark(1.2B,3 阶段半自归),每段:

```
每段 = max( 权重 4.53GB ÷ 草稿有效带宽(命中25%), FLOPs÷算力 )
       + 0.15×min + 0.25×通信常数
```

- 草稿 KV 扫描 = 主模型 KV × 15%(半自归要看上下文)
- 3 段合计 = 3 × 0.588 = **1.764 ms** → **c = 1.764 ÷ 2.479 = 0.71**

### 2.4 组装

```
τ = (1−0.72^6) ÷ (1−0.72) = 3.07 tok   (α=0.72, γ=5 的几何公式)
S = τ ÷ (η + c) = 3.07 ÷ (1.075 + 0.71) = 1.72×
```

τ 低于 η+c = 1.79 就亏本,对应保本接受率 α ≈ 44% — 这就是"τ 是收益、η/c 是成本"的含义。

### 2.5 三种部署的公式差异

| 部署 | 差异点 |
|---|---|
| 同卡串行 | 草稿与主模型抢同一套带宽/算力,草稿耗时 100% 计入 c(上例) |
| DT 串行 | 草稿在独立硬件跑同样的 roofline(换成草稿设备带宽/算力);通信 = 每方向(固定延迟+字节÷链路带宽),下行 B×(γ+1)×6B、上行 B×τ×读取层×隐层×2B,全部计入 c |
| DT 异步流水线 | 草稿预算 Eq.3 = T_pred(1) + R×T_pred(&#124;S&#124;) + (J+1)×T_pass(&#124;S&#124;) + T_host;塞进验证窗口的部分不计时间,停顿 = max(0, 预算−t_verify);miss 期望 = Σ P(miss=m)×T_fallback(m)(二项分布,B=1 退化为 (1−p_hit)×T_fallback) |

### 2.6 τ 从哪来 + 解码设备预设

- 同卡/串行:几何公式(见 2.4),α 可被 prefix 缓存加成
- 异步流水线(JetSpec++):τ = p_hit×τ_hit + (1−p_hit)×τ_miss,取论文实测网格(7 基准 × J/R 组合)×流水线损失因子;**τ 和 p_hit 都是滑条,可手动覆盖**,非校准模型默认借用 Qwen3-8B 数据并有警告
- 解码设备预设(Rubin/H100/LPX)只改 Target 侧的带宽/算力/命中率滑条;"片上需容纳"提示 = 权重+KV 每卡字节,判断命中率是否物理可达

## 3. Serving 仿真(离散事件引擎)

**物理校准:三点定解。** 用同一次仿真里三个稳态点解出二次曲线系数:

```
decode: 单步耗时 = W + a×B + c×Σctx     (B=并发, Σctx=总上下文)
prefill:        = Wp + g×L + p×L²
```

有 B 项 = 有并发后的权重重读;有 Σctx 项 = KV 变长;有 L² 项 = attention 平方项。拟合质量看 fit_error。

**调度语义**(对齐 SGLang 系):新请求准入(NTR)、超载回退(retract)、KV 槽位追踪;coloc 模式下 prefill 与 decode 共享时钟,干扰效应由事件推进自然涌现。

**profiling 校准层**:有真实测速 CSV 时,把物理曲线按算子分类(attention/FFN/其它)乘以"实测÷物理"因子;三护栏——网格覆盖 2×、因子可信带 [0.1,10]、只告警不阻断。**这是提高可信度的正道:用实测修正假设。**

**Agent-X trace 注入**:上传真实请求序列替换合成负载。

## 4. MAGI-2 视频管线

五阶段流水线,每阶段单独算 roofline:
外部 LLM → 文编(Qwen3.5-27B)→ 去噪(114B MoE,100 步×CFG 批内双份)→ Refiner(6.72B,5 步×2 次前向,窗口注意力)→ turbo VAE 滑窗解码 ∥ 音频 VAE。
**核心输出是显存时间线**:五类口径(常驻/阶段激活/累计缓存/瞬时临时/其他),每时刻总占用 = 并发存活项之和,峰值必须闭合(有断言)。

## 5. Matrix-Game 交互渲染

游戏引擎管逻辑 → 低模帧编码为控制 latent → 5B 因果 DiT 逐帧自回归 → VAE 流式解码,每 chunk 出 4 帧。
**关键口径:有界滑窗 KV**——窗口固定 21+1 帧,不随时长增长(与 LLM decode 的 KV 无限增长相反),时延按"每 chunk 预算 4000/fps ms"校验帧率。

## 6. MiniMax H3

Qwen3-VL 文本编码(前 50 层)→ Token Refiner(2 层)→ 50 层 MMDiT 去噪(video+audio+text 单流联合 varlen 注意力,CFG 蒸馏 1 次前向/步)→ 双 VAE 并行解码。逐项按官方推理代码核实。

## 7. DT 逐事件仿真(PR#5 新增)

解析式给的是期望值;事件仿真把每轮拆成依赖事件(预测/候选/精炼/发布/验证/传输/回退),按资源队列推进。首轮从普通草稿启动,之后每轮预演下一块,允许反馈与预演重叠。支持:缓存命中模式(独立采样/全 hit/全 miss/指定 H/M 串)、双向链路队列(共享或独立)、随机种子。输出跨轮 SVG 时间轴 + Perfetto 导出。**用途:看 p99 和跨轮重叠效应,补解析式的不足。**

## 8. HBM 日志分析

npu-smi 采样(约 3 秒一帧的显存总量)× 服务日志阶段时间戳,做 join 后得到各阶段(文编/去噪/VAE)的显存均值与峰值。去噪起止由 tqdm 行的累计时长反推。

## 9. 硬件表与比值

硬件表只有四个数:峰值算力(FP16/INT8/FP8/FP4)、显存带宽、显存容量、片上缓存。派生:
- **宽容比** = 带宽 ÷ 容量(每秒刷一遍显存的次数)
- **存算比** = 带宽 ÷ 算力(roofline 齿点的倒数)
- **齿点** = 算力 ÷ 带宽(FLOPs/Byte,算术强度超过它才受算力限制)

## 10. 全局假设与误差边界

**内置常数(非实测)**:MFU 0.75(分析视图 MAGI 用实测修正的 0.4)、投机收益视图访存/计算重叠 0.15。分析视图无此打包系数——norm/激活/rotary 等逐元素算子单独建条目:无权重、纯访存(字节÷带宽)。

**只读 config 的四类误差**(详见评审记录):
1. 连接方式:跨层 KV 共享等 config 看不出,KV 可能高估
2. 算子形态:MLA/SwiGLU/QK-norm 等实现差异,KV 误差可达 50 倍(DeepSeek 已写专用公式)
3. 训练/推理不对齐:量化布局、kernel 替换
4. 执行层:MFU、融合、通信、调度全未算

**可信度排序**:短上下文 decode 量级 > 长上下文 decode > prefill/大 batch 绝对值;**倍数对比 > 绝对数值**。

**校准路径**(提升可信度,成本递增):① profiling 按算子修正(serving 已有通道);② 源码核对确认 forward 假设(#7/8/9 的方向,需改成默认关闭的开关);③ 关键算子真机测速替换硬件表。
