G-P0-1 块并行草稿与链式参数矛盾 §4.1 接受模型仅按单参数 $\gamma$ 定义链式公式 $E[n]=\sum_{i=0}^\gamma \alpha^i$；而 §4.2/D-6 纳入了并行块方法 DFlash （iters=2）和 DFlash2 （block=8, iters=1）。 用同一个 $\gamma$ 既代表“草稿串行前向步数”又代表“验证候选数”，会导致 DFlash2 被错算成 8 次串行草稿 decode（时延高估约 7 倍） ，或者草稿单步 GEMM 的 $M$ 被错算成 $1$ 而非块大小 $8$！ 在 SpecMethod 与 IterationTemplate 中解耦三个正交参数： 1. propose_steps ($S_{draft}$，草稿串行步数) 2. draft_step_tokens ($M_{draft}$，每步并行生成数) 3. verify_tokens ($K$，目标验证候选数) 链式方法 $(S=\gamma, M=1, K=\gamma)$；DFlash2 $(S=1, M=8, K=8)$；DFlash $(S=2, M=B, K=B)$。 
G-P0-2 验证回退与下一轮 Bonus Catch-up 漏算 §4.2/§4.5 提到“接受/回退”，但未定义 $n < K+1$ 时的 KV 回退成本，更漏掉了 下一轮草稿首步如何消化上一轮目标产出的 bonus token 。 在 vLLM V1 SpecDecode 中，当目标验证接受了 $n$ 个 token（含 1 个目标采样出的 bonus token），草稿模型上一轮并未算过该 bonus token 的 KV（若 $n=K+1$，草稿连第 $K$ 个草稿 token 的 KV 也没写！）。因此 下一轮草稿第 1 步的输入 token 数是 $M_{draft,0}=2$（而非 1） ，且在 DT 分离下目标必须向草稿回传 $(n, \text{bonus\_id}, \text{hidden}[1..n])$！ 新增 RoundTransitionSpec （轮次边界状态转换契约） ： 1. 目标侧写 $K+1$ 槽位 KV，拒绝槽位 $(K+1-n)$ 执行 Paged KV 逻辑指针回退； 2. 下一轮草稿首步显式计入 catchup_tokens = 2 （链式）的算子与 KV 写账本； 3. DT 通信双向化：不仅计 draft→target 候选消息，还计 target→draft 验证结果与 bonus/hidden 回传消息。 
G-P0-3 异构 DT 分离的 Recipe 单一化与流水线悖论 ① §4.9/§4.10 将 RecipeSpec 定为全局唯一字段； ② §2 将“④ DT 分离流水线（草稿轮与验证轮重叠）”放入 M2 单请求解析矩阵。 ① 异构 DT 分离 下（如主模型在 H200 跑 vllm-cuda FP8 FlashMLA ，草稿在 L40S 或昇腾 910B 跑 BF16 FA / vllm-ascend ），主模型和草稿模型的设备与 Recipe 根本不同，全局单一 RecipeSpec 无法表达！ ② 单请求下第 $t+1$ 轮草稿依赖第 $t$ 轮验证结果，若强行重叠必有 分支猜错冲刷率 $(1-\beta)$ ；只有 跨微批（Micro-batch $B\ge 2$）交错流水 才能无损重叠。 ① 将 DeviceSpec + ParallelPlan + RecipeSpec 绑定到每个 RoleBinding （target / draft / prefill / decode） ，支持跨卡型、跨精度、跨引擎异构 DT； ② 将 DT 流水线拆分为两个显式模式： dt_pipe_microbatch （双微批交错无损重叠）与 dt_pipe_speculative （单请求超前投机，带分支命中率 $\beta$ 与冲刷惩罚）。 
G-P1-1 首发模型 DeepSeek V4.1 Flash 验证步的 MoE 与稀疏 KV 非线性放大遗漏 《仿真原理》§5 写“verify 一次 M=5 的大前向，权重读不变”；《重构方案》§4.2 仅给 DSpark 标注“仅 MoE 草稿随批量放大”。 首发主模型 DeepSeek V4.1 Flash 本身就是 MoE + CSA2 稀疏注意力模型！ 当 verify 一次输入 $K+1$ 个 token 时： ① 主模型 MoE 层的路由专家并集随 $M_{eff}=B(K+1)$ 按超几何分布显著放大， 主模型权重读取绝非不变 ； ② CSA2 稀疏注意力（topk=512+swa=128）在 $K+1$ 个连续查询 token 上既有前缀共享收益，又有稀疏块并集扩散系数 $\eta_{sparse} \in [1, K+1]$。 在 L1 cost_kernel 中将 MoE 专家并集函数 $U(M_{\text{tokens}}, E_{\text{total}}, k_{\text{top}})$ 与 Verify 共享前缀 / 稀疏块并集系数 $\eta_{\text{sparse}}(K+1)$ 提升为主模型与草稿模型通用的第一性公式，不再局限于 DSpark 草稿。 
G-P1-2 界面“形合神离”：工作台与对比页被再次拆开 §4.7 设计了“工作台（结构+算子+时间轴）”，却又把“加速比矩阵、K与γ扫描、方法对比”拆到独立的 “对比页” 。 这直接违背了你提出的 “界面上尽量把这几个功能合理的整合起来，而不是为了方便，把所有功能完全拆开” ！如果看加速比矩阵在 A 页、看时间轴和算子 roofline 在 B 页，用户在分析“为什么异构 DT 在 $\gamma=6$ 时加速比拐头”时就必须来回切页。 重构为真正的 “一屏四联动工作台（Single-Canvas 4-Way Workbench）” ： 1. 左上面板 即为【加速比矩阵与扫描导航器】； 2. 点击矩阵任意格 $\rightarrow$ 同屏联动刷新【右上：逐层网络结构 DAG】、【右下：算子 7 维透视卡 + 交互式 Roofline】、【底部：主/草稿/通信双轨时间轴】； 3. 支持 “钉住基线（Pin Baseline）” ：同屏所有视图同时显示当前方案相对基线的 $\Delta\text{ms}$ 与加速比拆解（见 Tab 4 交互原型）。 
G-P1-3 两份 HTML 拆分交付、层级命名漂移与本地死链 分成两个 HTML 文件并用相对路径互链；且《重构方案》称 lowering 在 L0 内，而《仿真原理》§6 称作 L0.5 lowering 。 在单文件预览器 / Canvas 中点击本地链接直接报错；两份文档对架构层级的称呼出现漂移，不利于作为 M0 冻结契约直接落地。 合二为一交付本 v3.0 全自包含单文件 HTML ，内置四大视图 Tab，统一固定为 L0a（数学结构 ModelIR）+ L0b（RecipeLowering → OpGraph） 的五层架构命名。

2 · 目标场景（北极星）与非目标 

NS-1 · 投机解码部署选型与加速比分析（第一优先级北极星） 
输入： 主模型（首发 DeepSeek V4.1 Flash ）+ 自定义草稿模型 （通过 HF config JSON 或参数直接构建）或内置方法预设（ MTP / DSpark / DFlash / DFlash2 ）；输入/输出长度（ISL / OSL）；接受率 $\alpha$、平均接受长度 $\tau$ 或经验分布；角色级设备与并行配置；部署方式矩阵 × 服务化特性矩阵。

4.1 术语表、链/块正交参数与接受率口径 Codex P0-3 Gemini G-P0-1 修订 
为同时精确刻画 自回归链式草稿（自定义小模型 / MTP / DSpark） 与 并行块草稿（DFlash / DFlash2） ，v3.0 将草稿提议参数解耦为三个正交字段，严禁用单一 $\gamma$ 混代： 
参数 / 术语 符号与物理定义 自回归链（MTP / DSpark / 自定义） 并行块（DFlash / DFlash2） 
propose_steps $S_{\text{draft}}$：每轮投机中草稿模型 串行前向调用的步数 （决定 launch 次数与权重重复读取次数） $S_{\text{draft}} = \gamma$（例如 $\gamma=4$ 则串行跑 4 步） DFlash2：$S_{\text{draft}} = 1$ DFlash：$S_{\text{draft}} = 2$（2 轮块迭代） 
draft_step_tokens $M_{\text{draft}}$：草稿每次前向处理的 活跃查询 token 数 （注意第 0 步需加 Bonus Catch-up，见 §4.5） 第 0 步 $M_{\text{draft},0}=2$（含上一轮 bonus），后续步 $M_{\text{draft},s}=1$ $M_{\text{draft}} = B_{\text{blk}}$（如 DFlash2 为 $8$，一次并行产出 8 个位置） 
verify_tokens $K$：目标模型单次验证的候选草稿 token 数； 目标模型验证前向的实际输入 token 数为 $M_{\text{verify}} = K + 1$ （含上一步已确认的末位/bonus token） $K = \gamma$，目标验证输入长度 $M_{\text{verify}} = \gamma + 1$ $K = B_{\text{blk}}$（如 8），目标验证输入长度 $M_{\text{verify}} = B_{\text{blk}} + 1 = 9$ 
提交长度 $n$ 一轮验证后实际提交写回的 token 总数 = 接受草稿数 $a \in [0, K]$ + 1 个目标采样 Bonus Token ，故 $n = a + 1 \in [1, K+1]$ 统一适用：$n=1$ 代表草稿全拒（仅产出 1 个目标 bonus token）；$n=K+1$ 代表草稿全接受并额外获赠 1 个 bonus token。 
接受率三选一互斥输入契约（优先级： committed_hist > chain_alpha > committed_mean ） 
输入模式字段 数学换算与物理语义 适用方法与边界校验 
chain_alpha: float ($\alpha$) 逐位条件接受率 $\alpha \in [0, 1]$，期望提交长度（已含 bonus）： $E[n] = \sum_{i=0}^{K} \alpha^i = \frac{1 - \alpha^{K+1}}{1 - \alpha}$（当 $\alpha=1$ 时 $E[n]=K+1$；当 $\alpha=0$ 时 $E[n]=1$） 默认用于链式方法；若用于 DFlash/DFlash2，表示块内前缀等效逐位条件接受率，UI 显式提示建议优先使用 $\tau$ 或分布。 
committed_mean: float ($\tau$) + includes_bonus: bool 直接给定每轮平均长度 $\tau$。若 includes_bonus=true ，则 $E[n] = \tau \in [1, K+1]$；若 includes_bonus=false （仅计接受草稿数），则自动换算 $E[n] = \min(\tau + 1, K + 1)$。 链式与并行块方法均适用；事件模式下采用 $[1, K+1]$ 上的 截断几何分布 反解参数采样，并在结果标注 assumption: truncated_geometric 。 
committed_hist: list[float] 经验概率分布 $[P(n=1), P(n=2), \dots, P(n=K+1)]$，$\sum P = 1$。解析模式取期望 $E[n] = \sum_{i=1}^{K+1} i \cdot P(n=i)$，事件模式按分布精确抽样。 最高优先级，支持实测日志回放与非独立同分布位置接受率。

4.3 D2 · 统一成本核：六类计数 + MoE 专家并集与稀疏 KV 定律 Gemini G-P1-1 新增 
L1 cost_kernel 是全仓唯一的物理公式实现层。除标准 Dense GEMM（$\text{FLOPs}=2MNK$）与五类字节账本（权重读 / 激活读 / 激活写 / KV 读 / KV 写）外，针对首发模型 DeepSeek V4.1 Flash 及 MoE 草稿，强制内置以下两条非线性物理定律： 


定律 1 · 主模型与草稿通用 MoE 专家并集扩散系数 $U(M_{\text{eff}})$ 
无论是主模型（如 DeepSeek V4.1 Flash 的 MoE 层）在执行 $M_{\text{verify}} = B \times (K+1)$ 的验证前向，还是 MoE 草稿（DSpark）在执行 $M_{\text{draft}}$ 前向， MoE 路由专家的权重读取量绝不等于单 token 常量 ，而是取决于 $M_{\text{eff}}$ 个 token 命中的去重专家并集期望数： 
E[U(M_eff)] = E_routed × [ 1 - C(E_routed - k_top, M_eff) / C(E_routed, M_eff) ] Weight_Read_MoE(M_eff) = Weight_Shared + E[U(M_eff)] × Weight_Single_Expert 
注：支持传入实测偏置系数 $\rho_{\text{skew}} \in (0,1]$ 修正非均匀热门专家分布。这直接决定了投机验证步 $K$ 增大时的真实带宽成本拐点。 

定律 2 · 验证步共享前缀 KV 读取与 CSA2 稀疏块并集系数 $\eta_{\text{sparse}}(K+1)$ 
目标模型一次验证 $K+1$ 个候选 token（上下文长度 $L_{\text{ctx}}$）时： 
全注意力 / 标准 MLA 吸收层 ：由于 FlashMLA / PagedAttention 将同一序列的 $K+1$ 个查询打包进同一 CTA Tile，历史前缀 $L_{\text{ctx}}$ 的 KV 缓存 只从 HBM 读取 1 次 （外加 $K+1$ 个新候选自身的因果写入与读取），即 $\eta_{\text{dense}} = 1$； 
CSA2 稀疏注意力层（DeepSeek V4.1 Flash： topk=512, swa=128 ） ：$K+1$ 个候选 token 各自检索 top-k 历史块，其读取的去重稀疏块并集为 $L_{\text{read}}(K+1) = \text{swa} + \eta_{\text{sparse}}(K+1) \cdot \text{topk}$，其中 $\eta_{\text{sparse}}(K+1) = 1 + \lambda_{\text{div}} \cdot K$（默认局部相关性系数 $\lambda_{\text{div}}=0.15$，可配置/校准）。

为什么这能优雅解决异构 DT 分离 ：当主模型部署在 8×H200 (TP8, vllm-cuda, FP8/FP4) 、草稿模型部署在 1×L40S (TP1, vllm-cuda, BF16) 或 1×Ascend 910B (TP1, vllm-ascend) 时，L1 对主模型算子调用 roles.target 的硬件与 Recipe 计价，对草稿算子调用 roles.draft 计价，跨角色传输调用 links.dt_inter 计价—— 无需写任何特殊分支代码 。 
单轮耗时闭式公式对比（解析核 L3） ： 
同卡串行 / DT 串行 ：$T_{\text{round}} = T_{\text{draft}}(S_{\text{draft}}) + T_{\text{comm, D}\to\text{T}} + T_{\text{verify}}(K+1) + T_{\text{comm, T}\to\text{D}}$ 
DT 微批流水线（ dt_pipe_microbatch ，$m \ge 2$） ：稳态单轮有效周期 $T_{\text{round}} = \max\big(T_{\text{draft}} + T_{\text{comm}},\, T_{\text{verify}}\big)$ 
DT 单请求超前流水线（ dt_pipe_speculative ，分支命中率 $\beta$） ：$T_{\text{round}} = \beta \cdot \max(T_{\text{draft}}, T_{\text{verify}}) + (1 - \beta) \cdot (T_{\text{verify}} + T_{\text{draft}} + T_{\text{comm}})$ 
4.5 D4 · 执行层：静态迭代模板 + 动态调度状态机 + 轮次状态转换 RoundTransitionSpec Gemini G-P0-2 新增 
每一轮投机迭代结束进入下一轮时，执行层强制执行以下三步状态转换（同时体现在算子账本与时间轴上）： 
Target KV 指针回滚（KV Rewind） ：验证前向写入了 $K+1$ 个位置的 KV，采样判定接受 $a \in [0, K]$ 个草稿后（总提交 $n = a+1$），退回未接受的 $(K - a)$ 个草稿 KV 槽位（PagedAttention 块表索引回退耗时 $\approx 1\sim 3\,\mu\text{s}$）。 
Target $\to$ Draft 结果同步（Verify Feedback） ：在 DT 分离部署下，通过 dt_inter 发送结果包（含接受长度 $n$、bonus token ID；若为 MTP 分离则附带 $n$ 个位置的最终 hidden states）。 
下一轮草稿首步追赶（Draft Bonus Catch-up） ：由于草稿上一轮未计算 bonus token 的 KV（且当 $a=K$ 全接受时草稿也未计算第 $K$ 个草稿 token 的 KV），下一轮草稿的第 0 步前向必须处理 $M_{\text{draft},0} = 2$ 个 token （末位确认 token + bonus token），第 $1 \dots S_{\text{draft}}-1$ 步恢复为 $M_{\text{draft},s}=1$。

区域 D（底部通栏）· 多轨推理时间轴（Target / Draft / DT Link / Verify & Catch-up） ：展示一轮投机迭代（或请求级）的精确时序条；点击时间轴上的任意阶段（如 Draft Step 0 (Catch-up M=2) 或 Target Verify (M=K+1) ），区域 B 的结构图与区域 C 的 Roofline 自动过滤并高亮该阶段的算子成本！

0 · 一句话第一性原理 

大模型推理性能仿真只回答一个问题：给定数学结构 $S$、引擎执行方案 $R$（Recipe）、工作负载 $W$、硬件拓扑 $H$，每个计算/通信单元消耗多少算力、访存、显存与时间，以及它们在时间轴上如何组合。 
它的全部底座只有一条三段式单向流水线： 计数 Count（算术/统计期望，精确可复算） $\to$ 成本 Cost（Roofline/链路物理模型，可被 T1 实测校准替换） $\to$ 执行 Execute（串行求和 / 关键路径重叠 / 离散事件推进） 。所有看似繁杂的部署模式、投机算法与服务化特性，全都是这条流水线特定位置上的 声明式改写器（Rewriter） 。 
1 · 四元组抽象：数学结构 $S \times$ 执行方案 $R \times$ 负载 $W \times$ 硬件 $H$ 
维度 物理含义与决定因素 为什么必须正交分离？ 
数学结构 $S$ ( ModelIR ) 由 HF config.json 与权重张量唯一确定：层序、层型（MLA / CSA2 / GDN / MoE / CED 半层）、隐藏维、头数、专家数与缓存字节语义（如 V4.1 Flash 的 890 B/token）。 框架无关的客观事实。无论用 vLLM 还是 SGLang，参数量、权重总字节与未融合 GEMM 主干 FLOPs 永远不变。 
执行方案 $R$ ( RecipeSpec ) 由 引擎 × 固定版本 × 角色硬件 决定：算子融合集（QKV 合并、SwiGLU 融合、RMSNorm+量化融合）、Attention 后端（MLA 矩阵吸收 vs 非吸收）、通信算子形态。 决定 lowering(S, R) → OpGraph 。融合省去了算子间中间激活的 HBM 读写并减少 kernel launch 次数——这是不同推理引擎性能差异的物理根源。 
工作负载 $W$ ( WorkloadShape ) 每个引擎步流经算子图的有效 token 形状：Prefill ($M=\text{ISL}$)、普通 Decode ($M=B$)、草稿提议 ($S_{\text{draft}}$ 步，首步 $M=2$、后续 $M=1$ 或块大小 $B_{\text{blk}}$)、目标验证 ($M=B(K+1)$)。 把静态 OpGraph 实例化为具体矩阵维度 $(M, N, K)$，并触发 MoE 专家并集 $U(M)$ 与稀疏 KV 并集 $\eta_{\text{sparse}}$。 
硬件拓扑 $H$ ( RoleBinding ) 每个角色绑定的设备峰值 TFLOPS（按精度）、HBM/DRAM/SSD 带宽与容量、Launch 开销、角色内/角色间互联带宽与延迟。 将与硬件无关的 Count 账本映射为物理时间（微秒/毫秒）与显存水位。异构 DT 本质就是 Target 与 Draft 绑定了不同的 $(R, H)$。 
2 · 三段流水：Count $\to$ Cost $\to$ Execute 

L0 · Lowering $S \times R \to \text{OpGraph}$ 融合算子、确立吸收式 MLA 形状 
→ 
① Count 计数 (L1) $\text{OpGraph} \times W \to \text{整数账本}$ FLOPs、五类访存字节、三类显存、激活形状 
→ 
② Cost 成本 (L1) $\text{账本} \times H \to \text{OpCostRecord}$ Roofline $t=\max(t_{\text{cmp}}, t_{\text{mem}})+t_{\text{launch}}$ 
→ 
③ Execute 组合 (L3/L4) $\text{OpCost} \times \text{部署/调度} \to \text{时序}$ 串行 / 流水线关键路径 / DES 事件流 
3 · 万物皆改写器：18 项功能统一变换表（v2.0 完整版） 
功能 / 特性名称 作用的流水段 精确物理改写规则 
算子融合 (Fusion) L0b Lowering $\to$ Count 将多个相邻算子合并为一个 FusedOpNode ，消除组内中间激活张量的 HBM Store/Load 字节，Kernel Launch 次数归 1。 
MLA 矩阵吸收 L0b Lowering $\to$ Count Decode 与 Verify 阶段将 $W_{UK}, W_{UV}$ 吸收到 Q/O 侧，KV 缓存只读写 512+64 维压缩潜向量（V4.1 Flash 混精后 890 B/token）。 
MoE 路由并集 $U(M)$ Count（期望化） 主模型 Verify ($M=B(K+1)$) 与 MoE 草稿的专家权重读取量乘以超几何去重并集期望 $E[U(M_{\text{eff}})]$，而非固定 $k_{\text{top}}$。 
CSA2 稀疏注意力 Count KV 读取长度由全长 $L_{\text{ctx}}$ 改写为 $\min(L_{\text{ctx}},\, \text{swa} + \eta_{\text{sparse}}(M_q)\cdot\text{topk})$；Prefill 额外计入候选池索引构建开销。 
CED 半层 Prefill 优化 L0a/Count DeepSeek V4.1 Flash 特有钩子：Prefill 阶段特定半层跳过冗余投影，按层号掩码精确扣减 FLOPs 与字节。 
TP / EP / PP 并行 Count + Execute 按角色切分算子 $(M, N, K)$ 与常驻显存，并在层内/层间插入 AllReduce / AllToAll / P2P 通信节点。 
链式投机 (MTP/DSpark/Custom) $W$ 改写 + Execute 每轮执行 $S_{\text{draft}}=\gamma$ 步草稿（第 0 步 $M=2$ 含 Bonus Catch-up，后续 $M=1$）+ 1 次目标 $M=\gamma+1$ 验证；产出除以 $E[n]$。 
块并行投机 (DFlash/DFlash2) $W$ 改写 + Execute 草稿步数缩减为 $S_{\text{draft}}=1\text{ 或 }2$，单步批量放大为块大小 $M_{\text{draft}}=B_{\text{blk}}$；目标验证仍为 $M=B_{\text{blk}}+1$。 
DT 分离（串行 / 流水） L2/L3 Execute Draft 与 Target 绑定独立设备与 Recipe；插入双向 dt_inter 消息传输事件，并根据串行/微批流水/超前流水组合时序。 
CUDA Graph W 对齐 + Cost 输入 token 数向上 padding 至捕获档位 $M_{\text{pad}}$（增加 Count），同时将逐算子 launch 开销替换为单次图回放常数（降低 Cost）。 
Prefix Cache / 分层 KV W 改写 / Cost Prefix Cache 削减 Prefill 计算长度 $(1-h)$；分层 KV 将超出 HBM 池的 KV 字节按 DRAM/SSD 带宽分段计价。

详见 Tab 2 §1.1 与 §6：旧仓之所以难以维护，是因为把上表中的“改写器”写成了互不通信的独立页面与平行计算函数。新仓通过 L0–L5 单向依赖彻底根除这一问题。 
5 · DeepSeek V4.1 Flash + 草稿模型完整手算算例（修正版） 

为什么重写原《仿真原理》§5 的手算例子？ 
原 §5 用了一个虚构的 40 层 Dense 4096 模型，得出“verify 权重读不变”的结论。但我们的首发模型是 DeepSeek V4.1 Flash（MLA + CSA2 + MoE 混精 + 890 B/token KV） ！下面给出直接用于 M1/M2 Golden 测试的真实机制手算链： 
步骤 / 阶段 物理过程与公式代入（单序列 $B=1, L_{\text{ctx}}=8192, \gamma=4, \alpha=0.75$） 手算关键结论 
1. 期望提交长度 $E[n]$ $K = 4$，链式接受率 $\alpha = 0.75$： $E[n] = \frac{1 - 0.75^5}{1 - 0.75} = \frac{1 - 0.2373}{0.25} = \mathbf{3.05\,\text{tokens/round}}$ 每轮平均前进 3.05 个 token（含 1 个 bonus token）。 
2. 草稿提议阶段 (含首步 Catch-up) 若采用自回归草稿（$\gamma=4$）： • Step 0：输入上一轮末位确认 token + bonus token，故 $M_{\text{draft},0} = 2$ ； • Step 1..3：每步输入 1 个新草稿 token， $M_{\text{draft},1..3} = 1$ 。 若采用 DFlash2（$B_{\text{blk}}=8$） ：仅执行 $S_{\text{draft}}=1$ 步 ，$M_{\text{draft},0}=9$，权重仅读 1 次！ 解释了为什么 DFlash2 在带宽受限卡上远快于 8 步自回归草稿。 
3. 目标验证阶段 (DeepSeek V4.1 Flash) 目标单次验证输入 $M_{\text{verify}} = K + 1 = 5\,\text{tokens}$ ： • 共享/Dense 权重读取 ：与 $M=1$ 相同（被 5 个 token 完全摊薄）； • MoE 路由专家权重读取 ：5 个 token 激活的去重专家并集 $E[U(5)] \approx 3.8 \times E[U(1)]$（而非 1.0 倍！），但折算到每产出 token 仍比单步 decode 省约 $35\%$ 专家带宽； • CSA2 稀疏 KV 读取 ：每个每层 token 原本读 $(512+128)\times 890\,\text{B} \approx 569.6\,\text{KB}$；5 个连续验证 token 共享前缀窗口，读取量为 $\eta_{\text{sparse}}(5) \approx 1.6$ 倍单 token KV 读。 精准刻画了 MoE 主模型在投机验证步下的真实带宽节省率（既不盲目乐观当成 1.0 倍，也不悲观当成 5.0 倍）。 
4. 轮次转换与回退 目标写出 5 个位置的 KV（$5 \times 890\,\text{B}/层$），采样接受 $n \approx 3.05$ 个后，Paged KV 块表逻辑指针回退 $5 - n$ 个槽位，并将 $(n, \text{bonus\_id})$ 传回草稿进入下一轮。 完整闭环 vLLM V1 SpecDecode 生命周期。
