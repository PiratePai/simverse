**结论**：四份冻结文档的指标数学抽样复核（MoE 并集数值、因果可见对数、E[N] 公式、60KB/64GB/s≈0.94μs 等）均无误，口径分层与“未知不填零”设计严密；主要缺口集中在五处——动态 K 与接受分布的联合律不可辨识、小尺寸 shape 证据不覆盖分支阈值、样本量/离散度未进入 Metric 协议、成本层在 V11 前无任何独立审计、跨指标对账不变量缺失。本轮为只读审查，未修改任何文件、未运行模型或测试；以下提议均不是已完成的验证。

## 高价值发现（8 项）

### Z2-01 动态 K × 边际接受分布的联合律不可辨识，解析 TPOT 会被静默算错
- **严重度**：高（必须修正，M2 开放解析比较前）；**类型**：工程修订（含 questions.md Q8 选项清单补一行，非新决策）
- **位置**：`ui-data-contract.md §4 M03`、§2 P01 SpecMethod 行、`questions.md Q8`、`principles.md §7`
- **已覆盖**：mean≠分布、α_i 条件链、动态 K 截断 N 与状态、K 上限/动态规则作为输入均已写明。
- **仍缺**：动态 K 的取值与接受事件相关（置信度截断即如此），但契约把「α_i/接受数分布」与「K 动态规则」登记为两个独立输入，未规定组合规则与可辨识性检查。
- **反例**：K∈{1,2} 各半，T(K=2)=10、T(K=1)=6（任意单位），E[T]=8。世界 A：α₁|K=2=0.9、α₁|K=1=0.5、α₂=0.8（边际 α₁=0.7）；世界 B：α 与 K 独立，α₁=0.7、α₂=0.8。两世界的契约输入（边际 α_i、K 分布/规则）完全相同，但 E[N]_A=0.5×2.62+0.5×1.5=2.06，E[N]_B=0.5×2.26+0.5×1.7=1.98，解析 TPOT 分别为 3.88 与 4.04——同一组输入产生两个真值，不可辨识。
- **最小修订**：CapabilityReport 增加规则——解析 E[N]/TPOT 仅当 (a) K 固定，或 (b) 输入为联合 (K, A|K) 分布或逐轮含 K 标注的 trace 时为 supported；仅有边际 α_i + 动态 K 规则 ⇒ support=approximated，reason="joint law of (K,A) unidentified"，且 M01 解析 TPOT、M02 解析加速比、M21 该维度扫描同步降级。Q8 输入清单补「联合 (K, A) 分布或跨 K 策略迁移声明」。固定 K 的首个场景（链式 MoE 代理）不受影响。
- **可执行验收例**：把上述 A/B 两世界写成 V03/V05 的 golden 枚举用例：系统对仅给边际输入的动态 K 场景必须输出降级标记或拒绝，绝不允许两次输出恰好相等的“默认合成值”。

### Z2-02 V02 小尺寸 shape trace 不覆盖维度阈值分支，FieldCoverage 会给出假覆盖
- **严重度**：高（必须修正，M1 退出前）；**类型**：工程
- **位置**：`plan.md §6-2`、`ui-data-contract.md §5 V02`
- **已覆盖**：源码 commit 固定、hook 盲区明示、“未跑 GPU 不宣称跑过”。
- **仍缺**：分支谓词常随维度取阈值（文档自己举证了 V4.1 indexer 的 short/非 short 路径随 `end//r` 切换），但 V02 只要求“小尺寸 CPU/meta trace”，未要求枚举分支谓词的维度阈值并在两侧各取证。
- **反例**：用 128 token 的 trace 建 V4.1 ledger 走的是 short 路径；生产 32k 上下文走非 short 路径、索引读随上下文增长（`principles.md §3` 自己的结论）。小 trace 会被当作结构证据挂在长上下文场景上，M11 索引流量口径随之错误，而 V01–V04 全绿。
- **最小修订**：source-map 必须列出每个分支谓词及其维度阈值；V02 的 shape-trace 矩阵须覆盖场景范围内每个阈值的两侧，或显式声明该分支 unverified 并把受影响指标降为 approximated。
- **可执行验收例**：对 indexer 阈值 r 各跑一次 seq_len<r、seq_len>2r 的 trace，断言两份 ledger 的 index_select 字节模型不同；再构造“scenario 超阈值但只挂小 trace 证据”的 run，capability 必须拒绝把 index 流量标为 counted。

### Z2-03 样本量/离散度只写在 M17，未进入 Metric 协议，采样类指标不可核验
- **严重度**：中高（必须修正，M2 结果协议冻结前）；**类型**：工程
- **位置**：`ui-data-contract.md §3 Metric 结构`、§4 M01/M02/M17/M21、§5 V08/V09
- **已覆盖**：statistic 区分 exact/expectation/sample/quantile/bound；M17 自身要求样本数、少样本标注；`principles.md §9` 区间三分类。
- **仍缺**：`Metric{value, unit, scope, statistic, ...}` 没有 `n_samples` 与离散度/区间字段——事件类 M01 TPOT、M02 吞吐、M21 扫描点都是随机量，单 seed 单请求值会以 statistic=sample 之名呈现为确定数；比较资格（V09）也无法做显著性判断。
- **反例**：两个 run 各 1 个请求的事件 TPOT 比率 1.08 即宣布“更优”；协议上没有任何字段暴露 n=1，V12 一致性检查照常通过。
- **最小修订**：Metric 增加可选但条件必填的 `n_samples` 与 `dispersion{kind: std/CI半宽/IQR, value, level, interval_kind}`（interval_kind 沿用 principles §9 三分类）；statistic∈{sample,quantile} 时缺失即 schema 错误。V09 比较资格增加“差异低于区间半宽 ⇒ not-significant”。
- **可执行验收例**：V01 schema 测试：statistic=quantile 且无 n 的 Metric 必须被拒；V12 E2E：n=5 的 p99 显示“样本不足”；n=1 的两 run 比率格显示“不显著”。

### Z2-04 成本层（T0 插件）在 V11 之前没有任何独立检查，常数/单位笔误可全绿通过
- **严重度**：中（必须修正；纯静态审计，不需要真机）；**类型**：工程
- **位置**：`plan.md §6-6`、`ui-data-contract.md §5 V01/V04/V11`、`principles.md §5`
- **已覆盖**：T0 只是估算、无机器保持 unmeasured、公式按量绑定 formula_id——这些声明不因本项重复。
- **仍缺**：V07 的“事件与解析相符”两侧共用同一 cost 插件，暴露不了常数错误；evidence 枚举（config/source-checked/shape-checked/counted/measured/fitted）里也没有“厂商 spec sheet 抄录”这一类型，设备峰值数字无独立来源可对。
- **反例**：把某设备 HBM 带宽录错 10×（或 GB/s 当 B/s 用），V01–V10 与 V12 全部通过，所有解析时间系统性偏离。
- **最小修订**：(a) 公式注册时强制量纲推导，结果不归约到 [时间]/[字节] 即拒绝；(b) 新增 evidence 类型 `spec-sheet`，设备 spec 峰值独立录入为证据对象；(c) 审计断言：每个解析 kernel 时间 ≥ max(F/P_spec, Q/BW_spec)（effective≤spec 恒成立，违反即常数错）。
- **可执行验收例**：注册一个 BW 少写 10× 的设备资产，量纲审计或下界审计必须红；合法资产全过。

### Z2-05 跨指标对账不变量缺失：M04/M16/M18/M19/M06 可各自“正确”却互相矛盾
- **严重度**：中（必须修正，随 V07 落地）；**类型**：工程
- **位置**：`ui-data-contract.md §4 M04/M16/M18/M19/M06`、§5 V07/V12
- **已覆盖**：ID 互通（round/message/allocation 互链）、V12 校验“忠实显示同一 bundle”、V08 只重算 TTFT/TPOT/吞吐/周期。
- **仍缺**：V12 校验的是“显示=产物”，产物内部跨指标的数值一致性没有验证步骤——M04 分解之和、M19 逐消息求和、M18 忙时积分、M06 峰值与 M16/M10 事件与分配账本之间无对账不变量。
- **反例**：M16 事件流里某 verify 阶段时长 ×2 而 M04 未同步，或 M19 消息字节与 M04 消息分量来自不同版本公式——每个指标单独看都自洽，UI 四视图联动显示矛盾数字，无任何测试报警。
- **最小修订**：trace-validator 增加不变量：per round `Σ M16 stage 时长 == M04 总时`；per round `Σ M19 消息字节/时长 == M04 消息分量`；`M18 busy 积分(由 M16 重算) == 报告利用率×墙钟`；`M06 峰值 == max_t Σ 存活 allocation（按 allocation_id 与 M10 join）`，浮点按登记容差。
- **可执行验收例**：golden 小 bundle 中人为改一个事件时长，≥1 条不变量必须失败。

### Z2-06 运行历史与场景复用没有页面/产物归属
- **严重度**：低中（可选后续，工程自决）；**类型**：工程
- **位置**：`ui-data-contract.md §2`（P01–P08 全表）、`questions.md Q10`
- **已覆盖**：run 状态、stale 标记、不可变快照、Q10 问历史 run 保留数量。
- **仍缺**：Q10 预设了“保留多少历史 run”，但八个页面没有一个owns“列出/检索/重开历史 run 与已存场景”的入口；产物表里也没有 run 索引对象。
- **反例**：研究者昨天扫了 30 个 run，今天无入口按 run_id/假设回看，只能重跑——与“改一个假设看变化”的核心目标相悖。
- **最小修订**：P01 增加历史抽屉（或 P04 增 run 索引），消费 experiments 的产物索引；场景保存/命名复用同理。
- **可执行验收例**：E2E——完成 run#2 后从历史入口重开 run#1，视图与首次导出同 content hash。

### Z2-07 V08 的 oracle 清单未覆盖 M18 利用率积分、M02 goodput、M17 分位数 estimator
- **严重度**：低（必须为文字修订，随 V08 实现落地）；**类型**：工程
- **位置**：`ui-data-contract.md §5 V08`
- **已覆盖**：V08 已含 TTFT/TPOT/吞吐/周期、E[T]/E[N]≠E[T/N]、窗口边界/取消/未完成。
- **仍缺**：M18 的 busy-share 积分、M02 的 SLO goodput（完成/取消混合）、M17 的分位数 estimator（最近秩 vs 插值）都是归约逻辑，同样可从人工 trace 独立重算，但清单未列，容易实现成“各写各的”。
- **最小修订**：V08 枚举清单补上述三项，并要求 estimator 在 M17 输入中登记后由 oracle 按同一 estimator 重算。
- **可执行验收例**：7 请求手工 trace（含 1 取消、warmup/drain 各 1）手算 p90、busy 积分、goodput，与 metric-oracle 输出对账。

### Z2-08 比较展示规则：比率必须伴随绝对值；多目标权衡视图缺位
- **严重度**：低（可选后续）；**类型**：工程 + 轻量用户偏好（可搭 Q9/Q11 的回答，不阻塞）
- **位置**:`ui-data-contract.md §2 P04`、`§4 M02`、`questions.md Q11`
- **已覆盖**：Q11 定单一主排序、资源约束比较另见 Q4；M02 记录 baseline ID。
- **仍缺**：UI 契约未要求比率格渲染分子/分母绝对值（“快 1.08×”而分母是 3ms 还是 300ms 不可见）；延迟/吞吐/显存之间没有帕累托前沿视图，资源预算相同的多方案比较只能看单指标排序。
- **反例**：研究者截图“加速 1.08×”放入报告，读者无从得知基线绝对值与样本噪声（与 Z2-03 叠加）。
- **最小修订**：V12 合约快照加一条显示规则——任何比率必须可展开两操作数；帕累托视图作为 P04 增量（非首发门槛）。
- **可执行验收例**：UI 快照用例“比率格展开显示两绝对值 + |Δ|<区间半宽时标不显著”。
