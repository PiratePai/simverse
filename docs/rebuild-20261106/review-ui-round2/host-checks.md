# 主控独立复核笔记（送审后，不提供给审查者）

待对照两位反馈后裁决，不先按共识定论。

1. V02 的 source/shape 能证明分支与维度，但不能证明数值语义；同形状改 mask、转置或 recurrence 更新都能逃过 shape 检查。需要明确模型小尺寸数值参考与其证明范围，不要求整个性能模拟器执行大型权重。
2. P01 的 ISL/OSL 有独立字段，但缺显式 phase/decode上下文更新与初始 cache 条件；M17 的 prefill 单词不构成 prefill 成本/缓存复用的可执行 schema。
3. 已有 token timestamp 不能唯一表示服务端提交与客户端可见：一次提交多个token时 ITL/SLO 取决于发包/释放策略。必须选择观察边界并记录事件；这是口径决策，不是自行拟造更平滑的时间线。
4. 证据沿依赖传播已有原则，缺依赖边类型、版本作用域和具体放行 predicate。完整计数与不完整物理资源不应被单一 supported 布尔混淆。
5. JSON/CSV 大整数已有约定提醒，但导出如何携带证据快照和分页完整性还需可验证定义。原文存档和结果重放不能互相代替。

本笔记为静态推理，没有新增源码或GPU运行证据。


## 对 DSH 初步裁决

- D2-01/03：采纳 policy 与排序字段，保留 Q4 默认总资源相同，不擅自改成额外卡默认合格。TPOT 排序应绑定 estimator/scope；prefill 增长本身不改变排除首 token 的平均间隔，原反例需改成尾轮/组批/输出释放差异。
- D2-02：采纳随机流算法、版本、语义键。拒绝“插入请求后事件时间完全一致”的验收：资源争用必然可能改变时序；动态 K/状态变化也可能改变接受过程。仅相同语义键/抽样分布的外生随机输入稳定，同输入同版本才要求相应重放级别。
- D2-05：采纳容量预算来源，必须避免先扣预留又将同一预留作为 allocation 重复计量；标称容量只能给可行性必要条件。
- D2-06：采纳 offered/executed/dropped/padded 账本；物理 FLOPs 可能计算 padding，不能全部只按 executed 有效assignment。
- D2-07：采纳统计单位/相关性；无真实trace仍允许明确假设下的模拟尾分布，不能声称实测或代表真实负载。
- D2-08：字段自报同样可能漏报，必须加受限可见状态 API 和未来信息扰动/变异负例；只检查现有边不够。
- D2-10：删掉原一般化周期公式，使用资源负载与有限 cohort 循环下界、具体调度。DSH替代max式仅在明确双stage资源划分下成立，不作通则。
