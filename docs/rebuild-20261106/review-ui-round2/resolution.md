## 2. 补充项和主控发现

- DSH 附加建议中的 K=0、batch/cohort ID、V09a/b 拆分、Prefix Cache 可解释数据已纳入。tokenizer hash 不同不能一概判不兼容，应检查 ID 映射/特殊 token/方法所需语义，未验证映射时拒绝。
- 主控独立提出的数值语义、prefill/初始 cache 条件、token 提交与客户端可见边界、证据域绑定与历史导出身份已合并到 §7.5–7.9。缺失完整 profile/长上下文分支/真实接受分布仍是缺口，不因审查者一致而消失。
- 不对 Engram/hc 立即增加专属 KPI；先让模型语义与通用工作/流量/容量字段覆盖，再依据独立 forward 证据判断是否需要新指标。跨服务 TP8+TP1、设备可用量和性能精度保持未证实。
- 每个 claim 的验证记录要写范围、前提、oracle 来源、负例与不能证明的部分；依赖污染按字段传递。详细设计不等于运行时已强制执行。

## 3. 本轮实际验证与边界

主控运行 [counterexamples.py](counterexamples.py)，结果 [counterexamples.json](counterexamples.json)，7 个独立算术见证通过：

1. 同 shape 的 attention，mask 不同会产生不同输出。
2. 相同 server commit，不同客户端缓冲策略会有不同 ITL。
3. 全局容量相同，rank 放置不同可能一者可行一者 OOM。
4. 窗口内 token 事件计数与窗口内完成请求 token 计数不同。
5. 动态 K 的同边际不同联合律给出不同 E[N]/解析 TPOT。
6. 错小十倍的 BW 同单位且仍满足时间下界，不能靠该检查抓错。
7. 两资源合法重叠的 service 总和不等于 elapsed。

这些程序不导入生产公式，也不调用模型；只检验审查推理与反例，不表示新后端、GPU、质量评测、流水调度器或上述 V01–V12 已通过。两位审查者的“抽样复核正确”也不是工具执行回执。未改 UI 代码，未重复上一轮 UI 截图检查。

主控另外校验文档本地链接、主编号与 region 覆盖、Q1–Q12 连续性、旧答复占位及本轮产物 hash；检查报告见 [doc-checks.json](doc-checks.json)。原始两份审查答复保留不改写，最终裁决以本文件和修订文档为准。
