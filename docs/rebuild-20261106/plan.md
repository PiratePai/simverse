# Simverse 重构计划：先建立可证伪的实验底座

状态：2026-11-09 用户决策修订版，Q1–Q12 方向性决策均已纳入；Q3 私有远端平台/地址待补。独立审查闭环见 [review-resolution.md](review-resolution.md)。

## 1. 结论与目标

继续新仓重构，但不把 new-viewer v0.1 的「13 项测试通过、差异归零」视为已建立正确底座。保留它的场景 JSON、统一 RunResult、CLI/Web/导出共用入口以及差异追踪方法；先重新核定模型/算法语义，再扩展能力。两个旧仓保持独立，迁移以场景和证据包为单位；不整体搬入旧计算逻辑与大型 vendored 依赖。UI 已确定直接复用用户 HTML 的工作台元素、样式和联动骨架；其中演示计算不进入生产链路。

用户已选择优先支持**新架构与系统方案实验**，其次解释模型和硬件瓶颈。本计划的第一项成功标准：研究者改一个明确假设，可以看到结构、工作量、流量、执行依赖和指标如何变化，也能知道哪个结论尚无依据。2026-11-08 用户明确两条必需场景：**DeepSeek-V4.1-Flash 作为主模型必须支持；Qwen3.6-35BA3B + DFlash 作为有明确主模型/草稿方案的配对**。Qwen 场景推进完整配对闭环，V4.1 同步补齐语义证据，其草稿配对尚未指定。主模型与草稿 checkpoint/revision、DFlash 结构和兼容性在接入时逐项登记，不按名称猜测或替换成原型 DFlash2 预设；在证据不足时允许查看结构和假设，阻断「已验证部署收益」结论。精确微型样例与四个历史模型作为独立回归锚点。

此轮交付计划、原理、审查记录及 UI 示例。没有修改三个项目的生产仿真逻辑，也没有进行真实模型/GPU性能测量。2026-11-09 用户确认新仓名称为 `simverse`，本地沿用 `D:/Github/new-viewer`，不迁移目录。共享模型结构包已确认放在新仓内作为独立子包，单独版本发布；远端可见性已确认为私有，托管平台/账号/地址待建远端前补充。`new-viewer` 的 Git 初始化状态在实际实施时复查，名称/目录决策本身不表示仓库已初始化或发布；本次没有擅自设置远端或提交用户已有文件。

## 3. 重新划清模型、方法和实现的边界

建议保持一个新仓内部单体包，模块职责明确，不先拆成多个服务或多个发布包：

```text
simverse/
  contracts/       版本化类型、单位、状态、来源、canonical serialization
  importers/       config/共享 ModelIR/forward evidence → 模型语义
  methods/         自回归、MTP、DSpark等提议与验证状态机
  lowering/        kernel recipe、量化、融合、分片、collective、缓存布局
  count/           确定性工作量、逻辑张量访问、容量对象
  traffic/         数据依赖的期望流量、复用/路由/缓存假设
  cost/            解析成本、profile模型、通信原语；禁止修改原始计数
  execute/         串行解析与资源约束事件执行
  serving/         到达、组批、预算、KV分配/回收/抢占（后续）
  experiments/     参数扫描、配对比较、敏感度、随机种子、产物索引
  api/ cli/ web/   同一结果协议的三个消费者
assets/            可追溯模型/设备/recipe/场景快照
validation/        手算锚点、forward证据、协议轨迹、真机对照
```

数据流：`Scenario + ModelIR → MethodPlan → LoweredGraph → Work/Traffic/Memory → Cost → Execution → ResultBundle`。事件执行时按当前 batch/ctx/state 调用同一 lowering/count/cost；不是一次启动就预先固定所有算子成本。

几个必须独立的身份：

- **模型**：层序、张量、权重共享、缓存producer/consumer。模型名称不能决定一切分支。
- **提议方法**：前向块、Markov head、置信度截断、采样/验收、状态追赶。`S/M/K` 是摘要字段，无法替代程序图；K也可能由置信度动态决定。
- **执行配方**：框架/commit/backend/kernel/dtype/shape/TP/EP/PP/graph模式。相同 ModelIR 可有不同物理实现。
- **部署**：角色放到哪个设备组、资源是否共用、链路拓扑；独立目标/草稿TP是研究能力，不能冒充某个vLLM内置路径已经支持。
- **负载与采样**：请求到达、ISL/OSL、batch、上下文、tokenizer兼容性、greedy/stochastic以及接受分布。

**Q7 已确认（2026-11-08）：首版以 HF 版推理代码为主要语义与 forward 参考，保留算子替换接口，推理引擎后续接入。** 每个模型冻结仓库/model revision、代码文件 hash、Transformers/PyTorch 版本、配置和实际 attention/算子 dispatch；HF 入口可能选择不同实现，不能只记“HF”就认为物理执行已固定。DFlash 的草稿与提议/验收方法绑定其实际来源，不能因主模型采用 HF 就假设方法已被同一路径完整实现。

算子接口沿用 `ModelIR → lowering → count/traffic/memory → cost` 边界：语义算子定义输入/输出、状态读写与副作用；implementation/recipe 插件定义支持的 shape/dtype/device、融合与物理布局；工作量和资源账本使用稳定 ID；成本插件消费该账本并保留版本/来源。更换实现会生成新 recipe/hash 并使受影响的旧成本与性能证据失效。语义等价替换需过小尺寸数值/状态对照、shape/分支和资源守恒；刻意改变架构语义则生成显式 ModelIR 变体，不能沿用原模型等价性结论。

**Q2 已确认（2026-11-09）：首版性能采用解析估算，保留 profile 校准接口。** 首版按阶段完成语义/计数/状态与执行正确性验证，T0 仍须独立参数、单位与手算审计；不以真机性能误差作为首版前置验收。

M2 在 cost 插件边界定义 ProfileRecord/CalibrationModel/CostEstimate：输入绑定 implementation/recipe/version、shape、dtype/layout、设备/软件环境和测量边界；输出保留 analytic_base、选用的估算/实测或拟合来源、coverage、外推/回退原因与证据。未覆盖可显式回退解析模型或返回 unknown，不能静默套全局校正倍数。profile 校准不得修改 ModelIR、Work/Traffic/Memory 原始账本；覆盖域或实现变更时重新判定适用性，并生成新运行身份。阶段 M2 以接口契约与合成 fixture 检查接线/失效/回退，不能将合成输入记为硬件校准；真实采集、拟合及留出误差验证在后续 M4 有数据时完成。

**Q8 已确认（2026-11-09）：首版采用显式假设扫描。** workload 与 acceptance 模块从场景读取 ISL/OSL、并发/到达、K/动态规则、条件接受率/接受分布与相关性假设，experiments 保存各扫描点输入、假设、版本与随机身份。具体参数范围尚未确认；演示默认值必须可编辑并标明来源。动态 K 缺联合信息时按现有能力闸门返回未知，只有显式登记的条件/独立性近似才产生相应估算。真实 trace 导入与新采集后续扩展，不是首版前置或首版必交付；保留数据源扩展边界即可。假设扫描不能证明真实接受率、任务质量或性能准确性。

**Q12 已确认（2026-11-09）：首版延迟与 SLO 采用服务端口径。** committed 与 server_emitted 分开记录和归约，具体指标绑定 time_basis，不默认两者相等；Q11 已确定多目标并列，各指标分别绑定边界。按实际/建模的批量释放政策生成时间戳，不把一次提交多 token 人为摊成均匀 ITL。客户端网络、缓冲与 client_observed 留作后续扩展；首版不依赖其实现，但服务端指标仍须满足到达/排队、窗口、phase、时钟域与样本充分性闸门。M2 无完整请求时间线时只输出已有解析口径，含服务调度的 TTFT/SLO 仍按 M4 能力开放。

**Q4 已确认（2026-11-09）：两种资源约束分别研究目标/草稿分离收益，并为异构性价比分析准备。** experiments 同时支持固定总设备型号/数量向量和固定目标设备组、草稿资源显式列出的比较；P04 以“分离收益”组织后一研究方向，不命名为扩容收益。使用同一主/草稿模型、方法、负载与质量约定建立混部↔分离配对；总资源、设备型号、TP/EP 或其他实现同时变化时，报告完整差异与归因局限。另用固定角色/部署策略下的草稿设备替换对照研究异构效果，不能把所有性能变化归于分离本身。

M2 保存资源/链路快照、角色放置、占用时长、两种 policy 与基线；无投机基线说明整体投机收益，混部基线说明所选条件下的分离收益，不能互相替代。后续以版本化单价/费用模型等明确成本口径计算异构性价比，保留成本来源/日期/计费范围及闲置资源处理；成本数据未提供时保持未知。V09a 检查两类约束分组与配对资格、分离/设备替换的因素登记，V08/V12 检查资源与未来成本汇总及导出一致性。首版仍按 Q2 采用解析估算，不因此承诺经济收益实测。

**Q11 已确认（2026-11-09）：多目标并列比较，不默认选单一赢家。** P01/P04 并列展示已有能力支持的服务端延迟、吞吐和资源，后续加入成本；分别使用 Q4 的两种资源政策。ComparisonPolicy 保存 objectives（metric/statistic/scope/time_basis/单位/优化方向），ranking_metric_ref 为可选的用户临时排序状态，不是必选全局目标。矩阵着色只表达当前明确指标，不能由单个加速比推断整体更优；不默认加权评分。无吞吐/成本模型时保留未知，不用 1/TPOT 或虚构单价补齐。M2 用多列对比和逐目标差异满足首版需求，帕累托图可后续增强。V09a/V12 验证排序/颜色切换不改变原始值与资格、两类资源政策不混排、未知维度不产生默认胜者。

M1 先冻结 HF 参考路径并建立模块/状态到逻辑图映射；M2 建立参考算子与可替换实现的注册/选择、计数和 T0 成本闭环。引擎适配放在后续扩展，首版不要求移植 vLLM 等引擎。TP/EP/跨服务方案仍可作为明确标注的研究配方建模，但 HF 源码本身不能证明相关部署已运行；实际支持、仿真假设和未来引擎验证分别登记。

已有 `mv_model_structure` 继续负责模型结构与forward证据，语义schema为唯一入口；新仓中的临时 `_v41_plan` 经独立测试后移入共享包，不保留永久双实现。Q3 已确认共享包从 model-verse 业务目录迁入 simverse 新仓，作为独立子包维护、单独版本发布；包的语义/schema 和版本契约独立于 Web UI 与仿真器成本实现。迁移时保留来源与许可，移除对旧仓内部相对路径的依赖；共享包不反向依赖仿真器或 UI。两旧仓固定发布版本/hash，通过薄适配器消费；禁止复制包代码，也不直接引用新仓源码路径代替版本依赖。后续如需拆仓，保留包名与兼容契约迁移，无需首发另建共享包仓库。

DSH提出的字段覆盖问题纳入M0硬门槛：每个配置键登记`mapped / metadata-only / ignored-with-reason / unsupported-semantic`，记录具体消费者与证据；未知语义字段使受影响结论降级。V4.1实际前40层比例是2个r0、18个r2、20个r1，另3项与草稿层的对应须显式表示，不能只用数组长度判断模型错误。Engram与hc路径在本次补读的vLLM实现中确实参与forward，当前账本缺失它们，不能继续发布完整模型容量/性能结论。

## 4. 结果协议与能力闸门

每个对象使用稳定 ID：`model/layer/logical_op/kernel/allocation/event/request/batch/cohort/round/message`；支持逻辑算子到融合kernel多对多映射。UI联动依赖ID，不能依赖名称、行号或列表顺序。

每个关键结果字段附带：`value, unit, scope, statistic, evidence_refs, assumptions, formula_id, input_refs`。`statistic`区分精确整数、期望、采样值、界；不把期望流量截成整数后称为精确计数。

采纳两位审查者关于实现负担的意见：来源、假设与公式存为去重字典，行只引用ID，阶段/配方可继承默认，异常覆盖。FLOPs、weight/activation/KV各分量和时间分别绑定公式，不能用一个`gemm_flops`解释整行所有量。公式函数的重放检查属于内部一致性测试，独立oracle仍必须另有推导。

状态分开表示：

| 维度 | 示例 | 约束 |
|---|---|---|
| 支持性 | supported / approximated / unsupported | 不支持的模块不填0；返回原因和仍可计算的字段 |
| 证据 | config / source-checked / shape-checked / counted / measured / fitted | 可同时存在、逐字段记录；没有单一「可信度90%」 |
| 可行性 | feasible / oom / invalid / unknown | OOM/未知容量不得进入有资格的收益/优劣比较 |
| 结果语义 | analytical-estimate / optimistic-bound / event-simulation / measurement | 理想下界不混入实测部署排名 |

RunResult里不存在的字段用`null + reason`，禁止 NaN/Infinity 的非标准 JSON。完整SHA256持久化，短hash只用于显示。运行身份至少包含输入、ModelIR、method、lowering/cost版本、硬件/校准快照、代码revision、随机种子；相同scenario_digest不足以保证版本升级后重放相同。

特性组合通过显式capability检查：例如未知量化kernel、未建模通信、缺草稿缓存/hidden协议、tokenizer不兼容、无证据的架构字段。允许探索模式继续输出独立可知部分，但污染路径的派生收益必须同时标记，并保留原始缺口。

## 5. 分阶段实施与验收

工期为单人专注开发的估算，依赖真实源码可得和机器可用，不是交付承诺。先做M0–M2形成可用闭环；后续按实验需求排序。

| 阶段 | 范围与交付 | 退出条件 | 估算 |
|---|---|---|---|
| M0 证据冻结与红灯 | 归档三个原材料及hash；引入现有测试；登记错误/近似/未知；建独立仓与最小CI；提交关键反例 | 每个报告结论能追到输入/公式/实现；已知错误测试会失败；确认数据来源和许可 | 2–3天 |
| M1 语义与计数 | 共享ModelIR版本；微型Dense/GQA、MLA、MoE、混合层序样例；V4.1 主模型与 Qwen3.6-35BA3B/DFlash 配对的证据图（DSpark 后续核实）；逻辑/期望/物理计数分层；第一版联动UI | 手算与独立枚举一致；shape trace与源码绑定；未知架构阻断；最小配置改动确实更新图与工作量 | 5–8天 |

**Q1 双场景准入：**M1 对 V4.1 主模型以及 Qwen3.6-35BA3B/DFlash 两个角色分别完成身份、配置覆盖与 forward 证据登记；M2 先让明确配对通过状态/协议/双方容量/计数/成本闸门，执行参考按 Q7 采用 HF，具体部署能力独立核实。V4.1 必须在支持清单中有独立验收项，不能因 Qwen 配对跑通就算它已完成，也不能把 V4.1 未指定的草稿默认为 DFlash。资产核实未闭合时显示阻塞与受影响指标，不能仅以模型名称进入收益比较。

**并行推进而非延期到最后：**M1就接回Qwen3-30B-A3B、用户称Qwen3.8的本地模型（以实际model_type/revision辨认）、Qwen3-Next和DeepSeek-V3作为结构回归，M2完成prefill/decode及TP1/8账本；M5只是旧界面接入和覆盖扩展。不同模型真实支持的TP集合必须由适配器校验，不盲测非法组合。

M2内设三个先后关口：**协议/部署能力先审定 → 资源与容量图闭合 → 成本计价和收益比较**。launch在M2随kernel recipe处理，不拖到事件核之后。DSH建议把各关口独立扩成M2–M4，采纳依赖顺序，暂不增加顶层里程碑。首版保留原 HTML 完整工作台的信息布局，按 M1/M2/M3 的数据能力逐区启用：M1 接结构/计数/证据，M2 接串行摘要、比较与 Roofline，M3 接合法并发事件。复杂大图布局可渐进增强，但不删掉既定信息入口；没有真实数据的区域显示缺口。本轮示例不作为正式产品已实现的证明。

**Q6 已确认（2026-11-09）：本地单用户工作台，JSON/CSV/trace/HTML 文件导出分享。** 首版采用本地服务与存储、浏览器工作台，不建设账号/云服务、远程访问或多人协作。导出由同一不可变 ResultBundle 生成，保留输入/版本/假设、比较政策、scope 和证据身份，并区分自包含快照与外部引用；用户自行分享文件，不自动发布。静态 HTML 不伪装为实时后端能力。V12 以 fresh run 检验四类导出字段一致及离线打开说明，历史重开按 content hash 检查。

**Q10 已确认（2026-11-09）：初期规模优先。** 本地单用户、单个活跃实验任务、每次扫描几十个方案，保留历史与大图/trace 分页，支持任务取消与扫描恢复；不先建设分布式队列或大规模任务并行。该约束属于工具执行层，不将场景中的请求并发、微批或资源事件简化为单请求串行。V10 增加单活跃任务门控、重复提交、点级完成清单/恢复幂等、取消清理和下一任务隔离；后续如开放并行任务，再完成相应并发隔离验收。具体参数上限、历史保留量和运行/打开详情的时延预算待真实产物测量后细化，当前不作性能承诺。

**Q5 已确认（2026-11-09）：DSpark → MTP → 自定义草稿模型 → Chunked Prefill → PD 分离 → Prefix Cache。** 此顺序作为扩展投入优先级，V4.1 主模型与 Qwen3.6-35BA3B/DFlash 仍是既定必需场景。M1 登记方法/模型证据，M2 在已建立的状态/协议/双方容量/成本底座上依次开放 DSpark、MTP 与自定义草稿兼容路径；自定义草稿须支持完整结构与方法绑定，不限于一个链式常数预设。M3 资源事件核是后续服务特性的正确性前提；M4 按 Chunked Prefill→PD 分离→Prefix Cache 分阶段接入，不因特性优先级而跳过依赖。

平台暂不设置 CUDA-first 或 Ascend-first：接口分离模型语义、逻辑算子、implementation/设备能力与成本资产；按实际取得的源码/配方证据逐组合开放支持。HF 参考不代表跨平台 kernel 等价，未实现组合返回原因，不以默认平台分支隐藏差异；该决策不要求首版同时完成两平台的真机测量。后续引擎适配仍遵循 Q7，不成为上述方法/服务模型的首版前置。

**首发明确暂缓：**所有视频/世界模型管线、训练仿真、跨框架完全等价、无profile的p99精确预测、所有投机方法一键兼容、整个前沿引擎vendoring。这些保留插件契约，不做空实现掩盖缺口。

## 6. 验证体系

1. **数学锚点**：GEMM、因果对数、GQA/MLA容量、MoE小集合枚举、通信字节、接受分布。golden的期望值不import生产公式；验证独立性靠推导和来源，不靠另建目录。
2. **结构/forward**：固定config+源码commit+分支条件；小尺寸CPU/meta shape执行；记录真实算子依赖、共享缓存、layer order。静态AST阅读与执行核验分栏，hook无法覆盖fused kernel时明示。
3. **lowering**：TP/EP分片守恒、复制开销、KV布局、packing/scales/alignment、融合消除哪些物化读写。整数计数在同一约定下精确相等；浮点容差按量纲/运算推导。
4. **协议/状态**：accepted/rejected/bonus token位置、草稿/目标cache length、消息体、commit/rewind/free的生命周期；A=0、A=K、EOS、K=0的普通decode独立分支、空batch、长上下文、显存边界。
5. **执行**：依赖和资源不变量、同输入同seed同结果；概率枚举/长序列统计验证解析期望。解析/事件相等仅限同一语义和资源假设，不要求复杂调度强行对齐闭式。
6. **硬件校准**：真实profile原始数据、设备/driver/kernel/版本、warmup/重复次数、分位数、留出集。误差门槛在看到结果前按使用目的预设；没有机器时状态保持unmeasured，不虚写「误差<5%」。
7. **应用一致性**：Web/CLI/export同run_id与内容hash；基线切换、过滤、单位、四视图联动。UI契约快照和一次关键交互端到端测试足够，不为样式重复造测试。

补充工程闸门：扫描接收不可变的设备/链路快照，不能临时修改全局注册表再恢复；并发run隔离、失败后清理与取消需要测试。CSV/export对比fresh RunResult的逐字段内容，不能只导出旧存档并检查行数。新仓采用标准UTF-8日志，修复本次测试暴露的子进程解码警告后才将CLI输出检查列为稳定验收。

## 7. 两旧仓迁移策略

迁移清单的单位是「模型revision × phase × batch/ctx × dtype/recipe × placement × method」。每项记录旧值、新值、独立期望、差异原因、证据状态；差异只有**修复正确性、近似变化、口径不同比较无效、未解决**四类，禁止用「已解释」作为自动通行。

优先迁移共享ModelIR→逐层账本→串行计算→事件导出→旧UI入口。旧计算器先保持可运行，只修阻断性缺陷；新旧同输入做shadow输出，新版达到结构/计数/状态/性能各自约定的门槛后再转入口。每次适配器升级固定wheel/hash，报告保留旧版本可重放。

新仓不直接依赖旧仓内部文件或任意相对路径。抽取代码先核对LICENSE，保留来源和必要声明；上游源码只存最小验证快照/指纹，完整参考checkout移出正式发布包。

**Q9 已确认（2026-11-09）：完整布局、逐区接入。** 首批在 M1 提供结构/计数/证据闭环，M2 接串行比较，M3 接合法流水事件；按各区数据与验证闸门开放，未支持区域保留并说明原因，具体日期尚未指定。

**已确定：直接复用原 HTML 工作台的信息结构、样式与交互元素。** 场景栏、Target/Draft 配方、七项摘要、部署方法矩阵、算子图、七维检查器、Roofline 与三轨时间轴均保留。原文审查、计划、原理继续作为资料导航；证据、配方、部署/内存与扫描详情逐步接入。完整页面/指标映射见 [UI 数据与验证契约](ui-data-contract.md)，复用范围见 [元素对照](prototype/reuse-map.md)。无需再次决策是否采用该 UI 方向。

该契约定义 **8 类页面/详情视图、23 组指标和 12 组验证步骤**，每项都有后端生产者、输入/单位/范围、缺失行为与开放里程碑。P02–P05 可先以抽屉或子视图实现，P06–P08 可继续使用版本化文档；不要求首版同时做八个完整应用页面。

| 阶段 | UI/后端联合交付 | 必须提供的证据 |
|---|---|---|
| M0 | 元素清单与页面/指标 ID；Catalog/Capability/ResultBundle schema；资料导航 | V01 身份及缺口登记；示例入口与生产数据隔离 |
| M1 | 后端模型/配方/层序/账本→算子图、七维字段、公式与证据；静态容量 | V02–V04 结构/数学/lowering，V12 同一 run 的显示/导出 |
| M2 | 状态/通信/内存/成本→七项摘要、矩阵、串行时间线、Roofline 与扫描 | V05–V10 的串行范围；每格独立 run、比较资格、每 rank 可行性 |
| M3 | 资源事件→微批/超前轨迹、周期/延迟、取消浪费 | V07/V08 并发、因果、请求指标；不能将周期代替 TPOT |
| M4 | profile 与服务请求→校准页、TTFT/尾延迟/SLO 指标 | V11 原始样本、留出验证、适用域与误差口径 |
| M5 | 两旧仓入口/存档→三方差异与回退 | V09 新旧/oracle 对账与 V12 全路径一致性 |

选择方案、层/算子或时间事件共享稳定 ID，逻辑算子与融合 kernel 允许多对多映射。修改参数使旧结果 stale；输入草稿与不可变 run 快照分离；晚到响应不能覆盖新场景。筛选只改变视图范围，不悄悄重算全局摘要。比较资格及正式派生指标由后端计算，Web/CLI/export 消费同一个结果。

结果先显示适用域和证据，再显示小数。模型结构不完整时保留已知图和缺口；OOM/容量未知只展示已知信息与原因，不参与有资格的优劣比较；steady-state 周期、解析 TPOT、请求 token 间隔、服务吞吐分别展示。原型中未绑定执行核的模拟数字不能作为生产接口失败时的回退；原版 JavaScript 演示公式须在生产接入时移出生产路径。

当前 [主工作台原型](prototype/index.html) 直接复用原版 HTML，数字为交互展示数据；[独立教学样例](prototype/teaching.html) 使用离线可复算预算。两者都不是生产执行核。保持原版完整存档只为追溯，不代表接受其全部公式与结论。本次只更新计划/契约，没有实现上述后端接口。

## 8.1 第二轮复核纳入的实施门槛

DSH 与 ZCode 已分别完成更新后冻结版本的只读审查，共提出 18 项主发现。原文、回执与逐项裁决见 [第二轮复核](review-ui-round2/resolution.md)。审查不是模型/GPU 验证；部分建议经修正后采纳，不能照搬审查者的测试公式。

| 关口 | 新增或收紧的实施要求 | UI/验证退出条件 |
|---|---|---|
| M0 / 契约冻结 | 每指标有 page/region；证据按 claim/domain/version 绑定；Metric 保存样本与区间身份；运行/场景索引 | M01–M23 全有入口；unknown/unsupported 与未测区分，历史结果不可变 |

| M2 / 串行收益前 | 动态 K 与接受/状态联合律；独立 RNG 流；显存可分配预算且预留不双扣；T0 厂商参数转录/单位/手算审计 | 缺联合律不静默算解析收益；同 scope 的工作/消息/容量/时间交叉对账；成本插件内部一致不当物理准确 |
| M2 / 比较与 UI | ComparisonPolicy 固定允许变量、资源规则、指标变体/样本单位；过滤作用域；比率显示绝对值；历史与 phase/cache 详情 | V09a 比较资格与 V12 显示/导出独立；资源增量明确；无足够样本不宣称统计胜者 |
| M3 / 流水与调度 | 独立必要依赖重建、受限可见状态、未来信息扰动负例；反馈/transition/资源竞争纳入周期 | 不再采用通用两阶段 max 式；V07/V08 分开核对 elapsed、busy、critical path 与 finite-cohort 边界 |
| M4 / 服务与校准 | token 提交/发出/客户端可见分型；时钟域/窗口/取消；保相关 trace 与边际重采样分型 | TTFT/ITL/SLO、分位数、goodput/busy 积分各有人工 oracle；profile/质量使用独立留出数据 |
| M5 / 迁移 | V09b 新旧/oracle 三方对账 | 不把旧入口切换误设为 M2 独立实验前提 |

具体字段与最小验收用例写入 [UI 数据契约 §7](ui-data-contract.md)。沿用 8 类视图、23 组指标、12 组验证主编号；新增内容归入现有指标子字段与 V02/V04/V09 等子步骤，避免平行维护第二套编号。

验证必须为每个 claim 写明“能证明什么/不能证明什么”。source/shape 不能代替数值语义；数值小例不能证明全模型质量或硬件延迟；低于标称容量不证明运行时可行；量纲和下界不能查出所有同单位常数错误；UI 与产物一致不能证明产物内部正确。已知错误变异未被抓住时，对应门槛不通过。依赖污染按受影响指标传播，保留不依赖缺口的已知部分。

这些要求按阶段启用，不把服务调度、尾延迟、overflow MoE 或可选帕累托图全部提前到 M1，也不延伸为重写上游框架。原工期仅作旧范围参考；新增门槛尚未做工作量实测，Q1/Q7/Q9 已明确，实施排期需按冻结后的首批范围重估，不能把新增工作隐含在原天数承诺内。
