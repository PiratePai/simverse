## 5. 验证要求

按 ui-data-contract.md 的 V01–V12 与子步骤实施，以下问题必须有明确反例/断言：
- source/shape 不能代替数值语义；检查 mask、位置、缓存、MLA 变换、recurrence 等所支持路径的小尺寸独立参考，以及真实源码分支阈值两侧。记录 oracle 依赖与不能证明的范围。
- GEMM/因果对数/Residual/GQA/MLA/MoE/接受分布等 golden 不 import 生产公式来生成期望；shape 一样、旧新一致或公式可重放都不是独立正确性证明。
- 动态 K 必须有联合/条件生成假设；边际均值不能静默合成分布；RNG 算法/版本/语义键固定。插入请求可能改变排队时间，不能错误要求事件时刻不变。
- MoE 区分 offered/executed/drop/reroute/padding、shared expert 与 rank 不均衡；逻辑/物理 FLOPs 不混淆。
- 显存按唯一同时存活对象和可分配预算检查，预留不双扣，不能用各对象独立峰值之和或标称显存证明可行。
- T0 有独立设备参数/转录/单位/手算审计；量纲或时间下界不保证发现同单位常数错误。profile 校准不覆盖错误语义。
- 事件验证要独立重建必要依赖并检查未来信息泄漏，不只检查调度器自报边；并行 service 时长之和不等于 elapsed；禁止套通用 max(D,V) 当 TPOT。
- 从人工轨迹独立重算 token 间隔、TTFT、吞吐、goodput、quantile estimator、busy 积分与容量峰值。明确窗口、样本单位、相关性、取消与未完成请求；不以 CI 重叠/单个半宽当通用显著性检验。
- 检验比较资格、双资源政策、全局/选择 scope、稳定 ID 联动、stale/晚响应、空/失败/取消/OOM/unknown、任务恢复幂等；单活跃任务也需隔离不同任务状态。
- fresh run 的 CLI/Web/JSON/CSV/trace/HTML 逐字段对账；UI 不重算另一套物理结果。做关键桌面/窄屏与交互验证，记录实际截图和导出证据，不能只报告静态语法通过。

无数据返回 null+reason；已确定不存在才是 0；unsupported/unknown/approximated、source/shape/count/measured/fitted、可行性、结果类型分别保存。全 SHA256 与版本化不可变快照支持重放，单位/大整数序列化不能丢失精度。源码阅读、合成 fixture、CPU/meta 执行和真实 GPU/profile 运行分别记账。
