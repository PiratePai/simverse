## 2. 官方 config 拓扑（identity 快照）与所有权

- `compress_ratios[0:40] = 0,0, 2×18(L2-19), 1×20(L20-39)`；`[40:43]`（MTP
  尾部）维持缺口不进主干层图。`sliding_window=128`、`index_topk=512`、
  `index_n_heads=32`、`index_head_dim=128`（RoPE 64）、`head_dim=512`。
- **kv source [2,8,14,20]**：持有 compressor（`fused_wkv_wgate`，**quant_config
  =None 的 replicated bf16**，FP32 kv_score 输出）、压缩 KV 缓存、indexer K
  缓存与 `wk/k_norm`。**index source [2,8,14,20,24,28,32,36]**：持有打分器
  （`wq_b` 量化 replicated + `weights_proj` **bf16** replicated）；非源压缩层
  复用下方最近源的 topk 索引，其 MLA 只读消费。
- **candidate 所有权**：候选缓冲 `[max_num_batched_tokens, 2048] int32` 为
  **模型级单例**（nvidia/model.py L793-798），仅候选源 **L20** 的 indexer
  写（`candidate_write=True`），仅 **>L20 的 index source（24/28/32/36）** 读
  作掩码（`0 ≤ candidate_source < layer_id`，attention.py L531-553）；
  MLA 注意力**不读候选**（只读 topk 索引）；跨层打分/消费由
  `SparseIndexTables` 等键复用去重（specialized sparse_mla.py L159-250，
  等键 = (kv源:索引源:r)，运行首层构建一次）。候选块 id 是源层压缩位置
  空间的块号（`candidate_block_size=8` 压缩位/块）——消费层与源层压缩比
  不同则坐标失配，vLLM 未显式断言，本仓在解析层按 config 域拒绝（负例测试）。

## 4. candidate/top-k 语义的独立 oracle（stdlib，不 import 生产公式）

- `select`：8 元块最大值 NaN 传播；最新块钉 +inf；全 -inf 块写 -1；top-k 取
  分值（**NaN 排最前**——torch.topk 与 decode_topk 的 order_key 把 NaN 键放
  在 +inf 之上、cooperative "pinned 除非 ≥k 个 NaN 块" 一致）。随机 40 列
  小尺寸对照 + 全 -inf 行只选钉扎块负例。
- `mask`：候选块内且因果内保留，其余列 -inf；候选行含 -1（padding）不掩任何
  块的负例。
- `fill`：`(pos+1)//r` 前取序号、其余 -1，恰满/溢出边界对照。
- 独立实现仅验证**对源码算法的解读**，非 kernel/CPU forward 数值执行；
  证据登记维持 source-checked。

## 6. 与任务书的出入及限制（如实；不冒充）

1. **短上下文旁路旧式 flops 误计修正**：旧 `index_select` 在旁路时仍计
   T·topk 选择 op；pinned `fill_short_context_topk_indices` 是纯 store
   （deepseek_v4/attention.py L77-92，无浮点运算，R05 expand 同类先例），
   修正为 `index_fill` 0 flops + T×topk×4 写。
2. **SWA/压缩记录宽度是设备族函数**：584（SM90 V4 record）/528（SM100
   V4.1 MXFP8）/288（nvfp4 仅压缩缓存）由 capability family 决定。本仓注册
   设备 H100/H200 均为 family 9.0 → 默认 `fp8_ds_mla_sm90`；以显式场景
   `v41_kv_record` 表达（进身份，同 engram_table_placement 先例），不从
   场景 kv 位宽推断（d×b_kv 旧式漏 scale/pad 尾部 72 B/token）。
3. **logits 按有效前缀计**：打分/候选/掩码/top-k 的 logits 读写按每行有效
   压缩位数 n_eff；CUDA-graph 静态 max_model_len 整宽缓冲的**整宽 -inf 尾写**
   与缓冲驻留未入账（engine max_model_len 是运行时常数）——登记缺口，不编造。
4. **选择 op 为文档化惯例**：top-k 2·n+k、块最大值 7·nblocks、掩码 4·n、
   combine 3·项为解析口径，非 kernel 指令数；cooperative 候选在值相等边界
   bin 为近似选择（≤k/1024 每簇，candidate_topk.py 文档）；decode_topk CuTe
   精确 top-k（任意顺序）语义与之一致，但其 SM100 专用路径不进默认配方。
5. **部署变体未建模**（默认 H100 配方不含）：SM100 `indexer_sparse_logits`
   （消费层只打分候选块，O(ctb·cb) 而非 O(ctx)——长上下文下是主要省略）、
   decode_topk CuTe BF16 直选、bf16 logits/deep_select、chunk_decode 预算、
   fused_mqa_topk、MXFP4 索引缓存（68 B/行）、TP≥2 且 uniform decode ≥12 行
   的行分片 + Lamport/NCCL all-gather、PCP/DCP、ROCm aiter/XPU、
   FlashInfer plain-row bf16 KV。
6. **注意力核本体不在本轮**：`sparse_attention` 行 flops 4d+5 与 bmm 尺度仍
   为 v0.1 移植口径（FlashInfer/FlashMLA sparse 核未 pin 逐行）；本轮只修
   其 KV 读字节（记录宽度）。structure_complete 仍 False；V4.1 不参与部署
   排名的结论不变（MoE scoring/量化映射/注意力核本体/MTP 尾部缺口）。
7. **config 域负例为本仓解析层约束**：candidate 消费层与源层压缩比失配的
   拒绝是 config 域不变式（vLLM 未显式断言；官方 config 无此形态），按
   "未知语义不得静默" 硬规则拒绝而非默认忽略。
