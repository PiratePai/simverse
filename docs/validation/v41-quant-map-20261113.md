## 1. 任务与结论摘要

官方 V4.1-Flash `quantization_config`（5 叶键）按 pinned dispatch 逐键映射：

| 叶键 | 值 | 源码语义 | 状态 |
|---|---|---|---|
| `quant_method` | `fp8` | model_type `deepseek_v41*` → override `deepseek_v4_fp8` → `DeepseekV41FP8Config`（config/model.py L1429/L1444-1465 override 链；quant_config.py L163-192；quantization/__init__.py L120-132 平台→子类） | mapped |
| `activation_scheme` | `dynamic` | 块量化硬要求（fp8.py L125-130）；激活 scale 不落盘（KDynamicNoParam，modelopt.py L2497-2510） | mapped |
| `weight_block_size` | `[32,32]` | 线性层走 MXFP8 分支的必要条件（quant_config.py L221-243）；checkpoint scale 32×32 块 → 装载展开 (N,K/32)（modelopt.py L2424-2479） | mapped |
| `scale_fmt` | `ue8m0` | **loader 不读该键**（fp8.py L155-172 键表无 scale_fmt）；有效 scale dtype 由 `expert_dtype=='fp4'` 派生（is_scale_e8m0，quant_config.py L89-93）。非 ue8m0 值按声明矛盾拒绝 | mapped（注记） |
| `expert_dtype` | `fp4` | config 类提升到 hf_config 顶层（transformers_utils/configs/deepseek_v41.py L46-50）；驱动线性 ue8m0 1B scale + 专家 Mxfp4MoEMethod（L244-261） | mapped |

四层口径分立（checkpoint 格式 / 运行时权重 / 计算精度 / 缓存精度）：

| 层类 | checkpoint 格式 | 运行时权重（注册设备 ≤SM90，stock） | 计算精度 | 缓存 |
|---|---|---|---|---|
| dense/attention 投影、共享专家（LinearBase） | MXFP8 e4m3 + ue8m0 32×32 块 scale（`weight_scale`） | 值 (N,K) 1B + scale 展开 (N,K/32) 1B（Marlin W8A16 重排；重排字节/workspace 未入账） | W8A16：激活 **BF16**（marlin.py L14 "SM80+"；FlashInfer MXFP8 核均 SM100+，flashinfer.py L47-53/L126-139） | — |
| 路由专家（RoutedExperts） | MXFP4 e2m1 打包 (E,2I,H/2)/(E,H,I/2) uint8 + ue8m0 (E,2I,H/32)/(E,H,I/32) | 同 checkpoint 布局，**分配前 Marlin 对齐 I→128、H→256**（routed_experts.py L190-203 + oracle/mxfp4.py L850-855） | W4A16：激活 **BF16**（oracle L461-486 SM90 优先级；Humming 为可选包变体） | — |
| embed/lm_head/RMSNorm/gate（R21）/compressor-wk-weights_proj（R20）/mHC（R05）/engram 表（R04） | 未量化（get_quant_method 对非 LinearBase/RoutedExperts/Attention 返回 None → 默认方法；vocab_parallel_embedding.py L318-340） | BF16 2B（mHC FP32、engram 表 264B/行不变） | BF16 | — |
| KV/压缩/SWA 缓存 | quantization_config **无缓存叶键** | 记录宽度由 R20 `v41_kv_record` 配方决定（584/528/288 B/token）；Fp8KVCacheMethod 仅显式 fp8 kv_cache_dtype 时加载 checkpoint scale（fp8.py L201-203/L845-849） | — | 不受本轮影响 |

**关键修正**（对账 before/after 见 §5）：此前 V4.1 全部激活按场景 `act=8`
计 1B、embed/lm_head/final_norm 按 dense_w 计 1B、专家/线性无 scale、专家
无打包对齐——四项均与 pinned 源码不符。R22 后：激活/未量化类 BF16、
MXFP8/MXFP4 scale 入账、专家打包 + Marlin 对齐入账。

## 6. 剩余限制（不宣称完成）

1. **执行变体未建模**（G-C14，登记不阻断结构门禁）：Humming W4A8
   （cc=90 优先于 Marlin、I→64 对齐、block-FP8(128) 激活——oracle L545-561）、
   SM100 TRTLLM/DeepGEMM/FlashInfer W8A8 mxfp8 动态激活（1B+K/32/行；
   注册设备无 SM100）、emulation 反量化驻留
   （VLLM_MXFP8_EMULATION_DEQUANT_AT_LOAD 默认开 → BF16 2B）、NVFP4
   moe_quant_algo 专家、expert_dtype=fp8 Flash-Base 块量化专家。
2. **Marlin 重排/补齐字节与 workspace、marlin_moe/marlin_utils_fp8
   is_supported_config 细节未逐项 pin**：驻留按 create_weights 分配口径
   （含对齐）计，重排等长变换与 workspace 缓冲未入账（峰值完整性
   unknown 传播不变）。
3. 计算精度成本档：Marlin W8A16/W4A16 在 bf16 Tensor Core 上执行，
   `cost.t0.dtype_route` 仍按 dense_w<16 → "fp8" 档计 GEMM 峰值（乐观
   算力上限）；未在本轮改成本路由（需 H100 marlin 吞吐证据，防无据改价）。
4. `scale_fmt` 为声明性键：loader 不消费；本仓按声明矛盾拒绝面外值，
   不静默取 expert_dtype 派生值。
5. 集合通信/激活字节为逻辑访问口径；逐 kernel 实际 HBM 流量未执行核验。
6. 历史 V4.1 replay 证据包（r05-mhc/csa2/moe-route，act=8）按 R21 口径
   冻结：其激活 1B 计价早于本轮口径，不作当前性能结论（当前口径以
   V41_QUANT + extras.quant 为准）。`tools/replay_v41_moe.py --check` 改为
   两层契约（R21 证据内部一致 + 当前代码复现 R22 证据）；一次性工具
   `replay_v41_csa2.py`/`replay_v41_mhc.py`（无 --check 模式）在场景装载
   即按新契约拒绝 act=8——不会再覆写冻结证据，重生成需显式按 R22 契约
   重建。工作台 UI 对 V4.1 固定发送 V41_QUANT（精度选择器对该模型不
   生效，JS 与后端同值）。

## 7. 结论

quantization_config 5 叶键全部 mapped；`structure_complete` 仍 False
（swiglu_limit、compress_ratios[40:43] 尾部、稀疏 MLA 注意力核本体缺口
不变，未提前解除其他门禁）；V4.1 的量化存储布局（块大小、scale 开销、
打包、TP/EP 分片）进入 count/traffic/memory 与证据注册，激活执行域按
注册设备（≤SM90 Marlin W8A16/W4A16 → BF16）固定，面外变体显式登记
unknown/未建模。
