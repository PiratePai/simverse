## 2. 逐项语义核对结论（全部有行号）

对照活跃 config（`deepseek_v41_config.json` text_config）；行号经二次逐行
复核（首轮验收指出引用漂移，已全部对实销行号更正）：

| 项 | config 值 | 源码语义（行号） |
|---|---|---|
| 打分函数 | `scoring_func=sqrtsoftplus` | `weights = sqrt(where(logits>20, logits, log(1+exp(logits))))`（dsv4_topk.py **L85**；>20 为 softplus(x)≈x 数值护栏）；CPU 侧 biased_topk_cpu 同语义（cpu_router.py L90-95 docstring 明言 "bias steers selection only"） |
| 偏置 | `topk_method=noaux_tc` | `e_score_correction_bias[E]` fp32（model.py L303-313）；**只导选择不进权重**：选择列 = weights+bias、NaN→−1e30（dsv4 L86-87），权重列 = 无偏 score（L96-98） |
| 分组选择 | **无分组** | V4.1 config 无 n_group/topk_group/num_expert_group 键（tests 断言）；router_factory.py L166-173 仅 use_grouped_topk（需显式组键）才走 GroupedTopKRouter——V4.1 走 FusedTopKBiasRouter 平坦 top-k（L215-238，选择点 L230）。pinned model 调用（model.py L426-449）未传 use_grouped_topk；工厂默认 False 已随 **fused_moe/layer.py 入 pin**（`use_grouped_topk: bool = False`），结论为平坦 top-k |
| top-k | `num_experts_per_tok=6` | 6 轮平坦 argmax、无放回（选中置 −inf，L102）；平手取**最小专家 id**（L94-95 `min(candidate)`）；NaN 分数 → −1e30（L87；在有限候选 score+bias > −1e30 域内 NaN 永不选中——护栏是常数，极端负 bias 的有限候选可低于它，域外不主张） |
| 归一化 | `norm_topk_prob=true` | `selected_weights *= routed_scaling/sum`（L104-107）；`weight_sum > 0` 为假（0 或 NaN）时分母取 1——sum=0 得全 0 权重，NaN 权重本身不被清除（护栏只改分母） |
| 缩放 | `routed_scaling_factor=1.5` | 并入上式单次乘法；**只作用 routed** |
| 共享专家 | `n_shared_experts=1`（inter 2304） | DeepseekV4MLP **无 gate**（与 Qwen3.6 shared_expert_gate 不同）；routed 归一后以权重 1.0 **独立相加**（moe_output.py L151-175 的 `shared_output` 契约）。V4.1 的 FusedMoEFactory 调用未传 `n_shared_experts`/`fuse_shared_experts`（model.py L426-449），故 `num_fused_shared_experts=0`，`fused_topk_bias_router.py` **L447-464** 的共享槽追加是通用能力、本模型未启用 |
| 路由 GEMM | `dtype=bfloat16` | GateLinear(h→E, bias=False, **out_dtype=fp32**)，ReplicatedLinear 子类（model.py L270-277，out_dtype 在 L274；gate_linear.py L26）。**权重**：未传 quant_config/params_dtype → LinearBase `params_dtype=torch.get_default_dtype()`、`quant_config=None→UnquantizedLinearMethod`（linear.py L287-295/L179-199），base_loader 在 `set_default_torch_dtype(model_config.dtype)` 内实例化（base_loader.py L86）→ official config bf16 下 BF16 2B。**输入**：不能由 model dtype 泛化——pinned mHC `tilelang.py` L900/L1096 的 `layer_input_cur` 硬编码 `dtype=torch.bfloat16`，`model.py` L731-816 把 fused_post_pre 输出直接传给 `self.ffn(x)`，故输入 BF16 2B。有效域固定 official V4.1 `dtype=bfloat16`；full_config 非 BF16 拒绝。`out_dtype=fp32` 只约束 logits 出口；每个 rank 全量、logits FP32 |
| EP 归属 | `n_routed_experts=384` | **mega 路径显式断言整除**：`n_physical(=E+eplb 冗余 0) % ep == 0`（L357-362，直接源码证据）。fused 路径 L419-421 的 `experts_start_idx = ep_rank·(n//ep)` 只是**初始化赋值、未被 FusedMoE 专家所有权消费**（全文件 grep 仅见赋值）；实际 fused EP 映射在 FusedMoE/ExpertMapManager（未入 moe-pin），不能据 L419-421 断言"非整除时尾部无 owner/与 generic 余数映射失配"。本仓因此只按 mega 断言把**建模域**收窄为整除组合（`require_divisible_ep` **保守域规则**）：不主张 fused 路径非法，只是不建模其通用余数分配；与 qwen35 pin 的余数规则分立 |
| hash MoE | — | V4.1 主干 `num_hash_layers=0`（v41 nvidia/model.py L155）→ 无 tid2eid 表；DSpark 草稿层（≥40）才覆写 E=128/k=3（L140-147） |
| VL 路由 | vision_config 32 层 | `vision_n_layers>0` → bias_vl[E] fp32 每 MoE 层创建（L314-320）、HAS_VL 哨兵逐行判定（dsv4 **L63-76**，5 个哨兵 id 才走 bias_vl；文本 token 也付 input_ids 读 + where 判定）；输出 FP32 weights + int32 ids（L149-150） |

关键澄清（对照旧仓公式/README 的差异）：
- **不是 V3 的 sigmoid+8 组 4 组选**：V4.1 无任何组键，平坦偏置 top-6；
- **权重不是 softmax/sigmoid 概率**：sqrtsoftplus 无界正分数，逐 token
  归一到 sum=1.5（不是 1.0）；
- **bias 不进权重**（noaux_tc 原义），与"分数+bias 排序取分数"的朴素
  实现在平手/护栏边界不同（NaN→−1e30、sum≤0 除 1）。

## 3. 建模落地（count/memory/IR/config 域）

- **count/moe.v41_moe_route_rows**（三行/层，per-rank 全量复制）：
  - `moe_gate`：FLOPs=2·T·h·E；**weight=h·E·2B、act_read=T·h·2B**
    （权重沿 model loader BF16；输入由 pinned mHC layer_input_cur BF16
    证明；不是场景 dense_w/act 的 8bit）；**act_write=T·E·4（FP32
    logits）**；每层 per-rank weight=3,932,160 B（旧账 1,966,080 B）；
  - `moe_score`：ops=T·(8E+vl)（sqrtsoftplus 5/elem + bias 加 1 + NaN 护栏
    2/elem；vl=E+2 视觉哨兵判定）、weight=2·E·4（bias+bias_vl）、
    act_read=T·E·4+T·8（logits+input_ids int64 上界）；
  - `moe_topk_renorm`：ops=T·[k(5E+3)+2k+4]（k 轮 argmax + 归一/缩放）、
    act_write=T·k·8（FP32 weights+int32 ids）。
  通用 `moe_router` 行在 v41 层被上述三行替换；`moe_routed`/`moe_shared`
  行不变（shared 无 gate 的既有事实与源码一致）。
- **model_ir**：extras["moe_route"] spec（scoring/topk_method/renormalize/
  routed_scaling/bias 字节数/hash_layers=0/grouped=False/**model_dtype=
  bfloat16、gate_weight_itemsize=2、gate_act_itemsize=2**）；四键逐行号
  注记；**config 域校验**：scoring≠sqrtsoftplus、topk_method≠noaux_tc、
  norm_topk_prob≠true 一律 ValueError（pinned 源码只支持该组合，不静默
  回退）。
- **lowering/memory**：每 MoE 层 `*-w-moe-route-L{i}` 对象 3,072 B
  （e_score_correction_bias 1536 + bias_vl 1536，FP32 复制不随 tp/ep）；
  `*-w-moe-L{i}` 的 **router_b 改为 h·E·2B=3,932,160 B/层**（GateLinear
  权重 BF16，不随场景 dense_w）；count 侧 moe_gate weight_capacity 与
  memory router_b 逐层对账，moe_score weight_capacity 与路由偏置对象
  对账（oracle 在册）。
- **EP 保守整除域**：count/build_model_work 与 memory/target_weight_allocations
  镜像 `require_divisible_ep`——V4.1 族非整除 EP（如 384%7）在**本建模域**
  直接拒绝；实际合法 TP/EP `{1,2,4,8}`（o_groups=8 约束）全部整除，
  E_l=384/ep 整专家。依据只有 mega 路径 L357-362 的 pinned 断言；fused
  路径 L419-421 的 `experts_start_idx` 只赋值、未被所有权消费，fused 通用
  余数映射（ExpertMapManager）未入 pin/未建模，故不据它断言 vLLM fused
  路径非法。登记为保守 config 域规则。
- **公式注册**：`v2.moe_route_gate/score/topk` 三条（expr+源码行号+适用
  条件）；证据 `ev-vllm-v41-moe`（source-checked，executed=False）；
  source_map `sm-v41-moe-route`（双侧覆盖）+ 旧 `sm-v41-csa2-moe-unverified`
  缩窄为注意力核本体/量化。

**structure_complete 不变（False）**：量化映射、swiglu clamp、稀疏 MLA
注意力核本体、compress_ratios 尾部缺口原样保留；MoE 部分解除的是
"csa2_moe_routing"一项，部署排名资格不因本模块解除。

## 4. 独立 oracle（tests/test_v41_moe_route.py，23 项）

- **§1 pin 完整性**：14 文件 blob sha1 对本地字节与 tree 双侧、SHA256、
  关键源码文本锚点（护栏/平手最小 id/EP 断言/Replicated/num_hash_layers=0/
  LinearBase 默认 dtype/UnquantizedLinearMethod/base_loader 默认 dtype/
  FusedMoEFactory 默认值）。
- **§2 语义 oracle（纯 stdlib，独立于生产公式）**：sqrtsoftplus 数值与
  >20 护栏、极小 exp 的 normal-range 近似（**−87.3 为 oracle 解析假设**：
  IEEE-754 单精度最小 normal 2^−126≈1.18e-38 → ln≈−87.3；低于此在 oracle
  取 0，subnormal/FTZ 未实测、非 pinned 源码断言，kernel 未执行）；
  sum(weights)==1.5 精确归一；bias 只改选择不改权重（逐 id 核对无偏
  score）；全平平手取最小 id；NaN 巨 bias 不选中（有限候选 score+bias >
  −1e30 域内）；全下溢 sum=0 → 除 1 护卫权重全 0；V4.1 config 无组键
  （平坦 top-k 的配置侧证明）。
- **§3 手算绝对值**：T=3 逐字段（gate 11,796,480 FLOPs / weight
  3,932,160B / act_read 30,720B / act_write 4,608B；score 10,374
  ops/3,072B/4,632B；topk 34,662 ops/144B）；40 层全模型三行；公式绑定
  不得挪用；实际合法组合 (tp,ep)=(1,1)/(2,1)/(4,1)/(8,1)/(8,8) 逐行复制
  不变（EP 仅允许 1 或等于 TP）；新增 gate 字节负例：Q8 与 Q4 场景下
  gate weight/act 不变（不得套用场景 quant），memory router_b 手算
  3,932,160B。
- **§4 EP**：ep=7 双侧（count+memory）拒绝（**保守域规则**：只有 mega
  路径 L357-362 的 pinned 整除断言；fused L419-421 的 start_idx 只赋值、
  未被所有权消费，fused 通用余数映射未入 pin/未建模，不据此主张 fused
  非法）；实际合法 TP/EP `{1,2,4,8}` 放行（3/6 虽整除 E，但被 o_groups=8
  的 ParallelPlan 拒绝）；ep=8 E_local=48、routed share 逐行复算。
- **§5 count↔memory 对账**：40×3,072=122,880 B 两侧相等。
- **§6 config 域负例**：softmax/grey/false 三非法值拒绝；vision=0 →

## 6. 剩余限制与接口依赖（不冒充）

1. **kernel/CPU forward/GPU 均未执行**（source-checked）；op 为解析算术
   口径（exp/log/sqrt/比较各 1，非 kernel 指令数）。
2. **部署变体未建模**：native MegaMoE（bf16_mega_gate 大批路径，需
   EP+fp4 专家+SP token 分片；deep_gemm 未入 pin）；GateLinear 的
   bf16 专核/cuBLAS 档未执行（fp32/bf16x3 分层只适用 fp32 router
   权重，V4.1 gate 为 BF16，不启用）；dsv4_topk Triton 档约束
   E∈{256,384}/k=6/fp32/renormalize（不满足落 ops.topk_hash_softplus_
   sqrt/CPU biased_topk_cpu——语义一致、指令构成不同）；E/k 其他值未独
   立核。
3. **DSpark 草稿层 MoE**（dspark_n_routed_experts=128/k=3、128 专家
   gate_threshold=1）：方法层字段（metadata-only），接口依赖已登记。
4. **quantization_config**（fp8/FP4 专家）不在本 PR：**gate 权重沿
   model loader BF16、输入由 mHC layer_input BF16 证明（均 2B；不是场景
   dense_w/act）**；有效域只覆盖 official V4.1 dtype=bfloat16，非 BF16
   拒绝；专家/其余 dense 权重的量化布局仍未映射，structure_complete
   仍 False。
5. padding skip（VLLM_MOE_SKIP_PADDING）、CUDA-graph 整宽路由缓冲、
   defer_moe_finalize（需 routed_scaling==1.0——V4.1-Flash=1.5 **不适用**，
   已按源码排除）未入账；VL 图像 token 的 bias_vl 选择分支只登记未选路。
6. input_ids 读按 int64 上界计；bias_vl 逐行重复装载按单次权重读计
   （寄存器/L2 效应不在逻辑账本域）。oracle 的 −87.3 是 normal-range
   下界近似（IEEE-754 单精度最小 normal，非 underflow 源码断言；subnormal/
   FTZ 未实测）；NaN→−1e30 护栏的"NaN 永不选中"主张限于有限候选
   score+bias > −1e30 域；sum≤0/NaN 护栏只把分母置 1，NaN 权重不被清除。
7. **ExpertMapManager 未入 moe-pin**：`fused_moe/layer.py` 已入 pin
   （`use_grouped_topk=False`、`fuse_shared_experts=False` 默认值可复验）；
   fused EP 的余数分配（ExpertMapManager.determine_expert_map）仍未入
   pin。EP 只按 mega 断言声明整除域，不据 fused 余数路径建模。
8. **共享专家实际路径**：V4.1 的 FusedMoEFactory 调用未传
   `n_shared_experts`/`fuse_shared_experts`（model.py L426-449），
   `num_fused_shared_experts=0`；共享专家由 runner 独立计算后加在 routed
   后（权重 1.0，moe_output.py L151-175）。`fused_topk_bias_router.py`
   L447-464 的共享槽是通用融合能力，不是本模型实际路径。

## 10. GateLinear 权重字节修复（2026-11-13）

**问题（高）**：`v41_moe_route_rows` 的 `moe_gate` 用
`quant["dense_w"]/8`（Q8=1B）计 gate 权重，`target_weight_allocations`
的 `router_b` 同样用 `b_dense`。pinned 链证明 **gate 权重沿 model loader
BF16 路径、gate 输入由 mHC layer_input BF16 证明**，均为 2B；每层
per-rank 少计 1,966,080 B，40 层少计 78,643,200 B（含 bias 的
weight_read 总 Δ78,766,080 B）。两者证据链不同，不能泛化成“任意 model
dtype 权重/输入”。

**源码链**（同 commit f358f057；gate 权重文件入 moe-pin 14 文件，
mHC 输入证据用既有 R05 pin）：
